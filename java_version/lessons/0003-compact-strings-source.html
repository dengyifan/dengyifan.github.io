JEPJEP 254: Compact Strings

背景：为什么 String 要改

Java 8 之前，String 内部使用 char[] 存储，每个 char 占 2 字节（UTF-16）。但绝大多数字符串只包含 Latin-1 字符（ASCII 的扩展），高 8 位都是 0——平均一半内存被浪费。

字符串Java 8 内存Java 9 内存节省
"Hello"10 字节 (5 char × 2)5 字节 (5 byte × 1)50%
"你好"4 字节 (2 char × 2)4 字节 (2 byte × 2)0%
"Hello你好"14 字节14 字节 (7 char × 2)0%
历史教训
JDK 6 曾尝试过 -XX:+UseCompressedStrings，通过 byte[] 存储 ASCII 字符串。但因为每次操作都要判断编码并可能解包（unpack），性能反而下降，JDK 7 被移除。Java 9 的方案解决了这个问题——用 coder 标志分发到不同的静态实现类，避免运行时转换。

逐段源码分析

3.1 String 类的核心字段（String.java:110-125）

public final class String
    implements java.io.Serializable, Comparable<String>, CharSequence {

    /**
     * The value is used for character storage.
     *
     * @implNote This field is trusted by the VM, and is a subject to
     * constant folding if String instance is constant. Overwriting this
     * field after construction will cause problems.
     *
     * Additionally, it is marked with {@link Stable} to trust the contents
     * of the array. No other facility in JDK provides this functionality (yet).
     * {@link Stable} is safe here, because value is never null.
     */
    @Stable
    private final byte[] value;   // 关键行: char[] → byte[]

    /**
     * The identifier of the encoding used to encode the bytes in
     * {@link #value}. The supported values in this implementation are
     *
     * LATIN1
     * UTF16
     *
     * @implNote This field is trusted by the VM, and is a subject to
     * constant folding if String instance is constant. Overwriting this
     * field after construction will cause problems.
     */
    private final byte coder;    // 关键行: 新增 coder 标志

    /** Cache the hash code for the string */
    private int hash; // Default to 0
}

分析：

  • value 从 char[] 改为 byte[]，这是 Compact Strings 的物理基础。
  • coder 是新增的 byte 字段，取值 LATIN1(0) 或 UTF16(1)。
  • @Stable 注解告诉 JIT：这个字段在初始化后不会变（虽然 value 是 final，但 @Stable 是更强的保证），这让 JIT 可以放心做常量折叠和逃逸分析。
  • 注意字段声明顺序：value → coder → hash，JVM 会按此顺序分配内存，对齐后有轻微性能优化。

3.2 length() 方法的分发（String.java）

public int length() {
    return value.length >> coder;   // 关键行
}

分析：

  • coder 是 0（LATIN1）时，value.length >> 0 = 字节数 = 字符数。
  • coder 是 1（UTF16）时，value.length >> 1 = 字节数 / 2 = 字符数。
  • 这是极高效的分发：没有 if-else 判断，没有方法调用，只是一个位移操作。JIT 编译后通常是 2-3 条机器指令。
设计智慧
用位移替代 if-else 是一个经典优化：coder 只有 0/1 两个值，正好对应“不移位”和“右移 1 位”。这种设计让 length() 这个高频方法几乎无开销。

3.3 isEmpty() 与 coder 的关系

public boolean isEmpty() {
    return value.length == 0;
}

分析：不需要考虑 coder，因为空字符串的字节数组长度为 0，无论编码是什么，value.length == 0 都成立。

3.4 构造函数：编码判定逻辑

在 Java 9 中，字符串构造时通过 StringUTF16.compress() 或直接拷贝决定编码。核心判定逻辑在 StringUTF16.compress()：

// StringUTF16.java
public static byte[] compress(char[] val, int off, int len) {
    byte[] ret = new byte[len];
    if (compress(val, off, ret, 0, len) == 0) {
        return ret;    // 全部 Latin-1，返回压缩后的字节数组
    }
    return null;       // 含非 Latin-1 字符，无法压缩
}

// 核心压缩循环
public static int compress(char[] src, int srcOff, byte[] dst, int dstOff, int len) {
    for (int i = 0; i < len; i++) {
        char c = src[srcOff];
        if (c > 0xFF) {
            // 关键行: 有字符超过 Latin-1 范围 (0xFF)
            // 立即返回非 0，表示无法压缩为 LATIN1
            return 1;
        }
        dst[dstOff] = (byte)c;
        srcOff++;
        dstOff++;
    }
    return 0;   // 全部压缩成功
}

关键设计：

  • 压缩是快速失败的——一旦遇到 > 0xFF 的字符，立即返回 1，不再继续扫描。
  • 返回 0 表示成功，返回非 0 表示失败。调用方根据返回值决定用 LATIN1 还是 UTF16。
  • (byte)c 是安全的窄化转换——因为前面已保证 c <= 0xFF，丢弃高 8 位不丢信息。

3.5 coder() 方法

byte coder() {
    return COMPACT_STRINGS ? coder : UTF16;
}

分析：

  • COMPACT_STRINGS 是 JVM 启动参数 -XX:-CompactStrings 控制的开关。
  • 如果关闭 Compact Strings，coder() 永远返回 UTF16，所有字符串按 2 字节/字符处理。
  • 这个设计允许运行期切换——虽然默认开启，但极端性能场景可以关闭。

charAt 的两种实现对比

StringLatin1.charAt（1 字节/字符）

public static char charAt(byte[] value, int index) {
    if (index < 0 || index >= value.length) {
        throw new StringIndexOutOfBoundsException(index);
    }
    return (char)(value[index] & 0xff);   // 关键行: & 0xff 转无符号
}

StringUTF16.charAt（2 字节/字符）

public static char charAt(byte[] value, int index) {
    checkIndex(index, value);
    // 关键行: 高低字节组合
    int hi = value[index * 2] & 0xff;
    int lo = value[index * 2 + 1] & 0xff;
    return (char)((hi << 8) | lo);
}

对比：

  • Latin1 版本只需一次数组访问 + 位与操作。
  • UTF16 版本需要两次数组访问 + 位运算组合。所以在处理 ASCII 字符串时，Latin1 版本天然更快。
  • 这就是 Compact Strings 的双重收益：省内存 + 部分操作更快。

完整可执行示例

public class CompactStringsDemo {
    public static void main(String[] args) throws Exception {
        // ===== 1. 观察内存占用差异 =====
        // 通过反射访问 String 内部字段验证 coder

        java.lang.reflect.Field valueField =
            String.class.getDeclaredField("value");
        java.lang.reflect.Field coderField =
            String.class.getDeclaredField("coder");
        valueField.setAccessible(true);
        coderField.setAccessible(true);

        String ascii = "Hello, Java 9!";
        String chinese = "你好，Java 9！";

        byte[] asciiValue = (byte[]) valueField.get(ascii);
        byte[] chineseValue = (byte[]) valueField.get(chinese);
        byte asciiCoder = (byte) coderField.get(ascii);
        byte chineseCoder = (byte) coderField.get(chinese);

        System.out.println("=== ASCII String ===");
        System.out.println("Content: " + ascii);
        System.out.println("Length: " + ascii.length());
        System.out.println("byte[] length: " + asciiValue.length);
        System.out.println("coder: " + asciiCoder + " (0=LATIN1)");
        System.out.println("Memory: " + asciiValue.length + " bytes");

        System.out.println("\n=== Chinese String ===");
        System.out.println("Content: " + chinese);
        System.out.println("Length: " + chinese.length());
        System.out.println("byte[] length: " + chineseValue.length);
        System.out.println("coder: " + chineseCoder + " (1=UTF16)");
        System.out.println("Memory: " + chineseValue.length + " bytes");

        // ===== 2. 验证 length() 的位移原理 =====
        System.out.println("\n=== length() 位移验证 ===");
        System.out.println("ASCII: value.length=" + asciiValue.length
            + ", coder=" + asciiCoder
            + ", length()=" + (asciiValue.length >> asciiCoder));
        System.out.println("Chinese: value.length=" + chineseValue.length
            + ", coder=" + chineseCoder
            + ", length()=" + (chineseValue.length >> chineseCoder));

        // ===== 3. 混合字符串使用 UTF16 =====
        String mixed = "Hello你好";
        byte[] mixedValue = (byte[]) valueField.get(mixed);
        byte mixedCoder = (byte) coderField.get(mixed);
        System.out.println("\n=== Mixed String ===");
        System.out.println("Content: " + mixed);
        System.out.println("Length: " + mixed.length());
        System.out.println("byte[] length: " + mixedValue.length);
        System.out.println("coder: " + mixedCoder);
        System.out.println("内存: " + mixedValue.length + " bytes"
            + " (长度 " + mixed.length() + " × 2)");

        // ===== 4. 运行期开关：-XX:-CompactStrings 时 coder 强制 UTF16 =====
        System.out.println("\n=== COMPACT_STRINGS 开关 ===");
        java.lang.reflect.Field compactField =
            String.class.getDeclaredField("COMPACT_STRINGS");
        compactField.setAccessible(true);
        System.out.println("COMPACT_STRINGS = " + compactField.get(null));
        System.out.println("(用 -XX:-CompactStrings 运行时此值为 false)");

        // ===== 5. 性能对比：ASCII 字符串长度计算 =====
        System.out.println("\n=== 性能对比 ===");
        String bigAscii = "a".repeat(1_000_000);
        String bigChinese = "字".repeat(500_000);
        // repeat 是 Java 11 引入的，Java 9 用 StringBuilder 替代

        StringBuilder sb1 = new StringBuilder();
        for (int i = 0; i < 1_000_000; i++) sb1.append('a');
        String bigAscii2 = sb1.toString();

        StringBuilder sb2 = new StringBuilder();
        for (int i = 0; i < 500_000; i++) sb2.append('字');
        String bigChinese2 = sb2.toString();

        long t1 = System.nanoTime();
        for (int i = 0; i < 1000; i++) bigAscii2.length();
        long t2 = System.nanoTime();
        System.out.println("ASCII length() 1000次: " + (t2-t1)/1000 + " ns");

        long t3 = System.nanoTime();
        for (int i = 0; i < 1000; i++) bigChinese2.length();
        long t4 = System.nanoTime();
        System.out.println("Chinese length() 1000次: " + (t4-t3)/1000 + " ns");
    }
}
反射访问的注意事项
上述代码用反射访问了 String 的私有字段。在 Java 9 JPMS 下，需要：
  • 启动参数加 --add-opens java.base/java.lang=ALL-UNNAMED
  • 或在 module-info.java 中写 opens java.lang（不可能，因为 java.base 是 JDK 模块）
  • 如果用类路径运行（未命名模块），加 --add-opens 即可

关键设计决策

决策为什么代价
byte[] + coder 而非 char[]Latin-1 字符串省一半内存所有 String 操作需 coder 分发
用位移而非 if-elselength() 等高频方法零分支开销可读性略降
静态方法分发到 StringLatin1/StringUTF16避免运行时解包，每个实现独立优化代码量翻倍（String.java 类膨胀）
快速失败压缩遇到 >0xFF 立即返回，不浪费扫描需要两次扫描（第一次判断，第二次构造）
保留 COMPACT_STRINGS 开关极端性能场景可关闭增加分支判断（但 JIT 可内联常量）
