一、语言与语法特性

1.1 JShell (REPL)

Java 长期缺少交互式执行环境。测试一个 String.format() 行为要创建类、写 main、编译、运行。对于快速验证 API，这个流程太重。JShell 提供了官方 REPL。
JShell 依赖 jdk.jshell 模块和 JDI（Java Debug Interface）。它用 SourceCodeAnalysis 分析片段完整性（Complete/Incomplete/Error），然后通过 JDI 在远程 JVM 中注入执行。变量可以重复声明，因为每次声明都在远程 JVM 中重新定义。

可执行示例

1.2 接口私有方法

Java 8 引入接口默认方法后，如果两个默认方法有共享逻辑，只能抽成 public 方法（污染 API）或复制代码。Java 9 的私有方法解决了这个问题。
接口私有方法在编译期被编译为 private 方法（Java 11 之前是 synthetic 方法），只能在接口内部调用。私有静态方法可以在静态和非静态接口方法中使用。

可执行示例

public interface Calculator {

    default int add(int a, int b) {
        validate(a, b);
        log("add", a + b);
        return a + b;
    }

    default int subtract(int a, int b) {
        validate(a, b);
        log("subtract", a - b);
        return a - b;
    }

    // Java 9: 私有实例方法
    private void validate(int a, int b) {
        if (a < 0 || b < 0) {
            throw new IllegalArgumentException(
                "Negative numbers not supported: " + a + ", " + b);
        }
    }

    // Java 9: 私有静态方法
    private static void log(String op, int result) {
        System.out.printf("[%s] result=%d%n", op, result);
    }

    static Calculator create() {
        return new Calculator() {};
    }
}

// 使用
class Demo {
    public static void main(String[] args) {
        Calculator calc = Calculator.create();
        System.out.println(calc.add(3, 5));       // [add] result=8 / 8
        System.out.println(calc.subtract(10, 4)); // [subtract] result=6 / 6
    }
}

1.3 try-with-resources 增强

Java 7 要求资源必须在 try() 中声明。如果已有 final 或 effectively-final 变量，得重新声明。Java 9 允许直接用外部变量。
编译器在编译时生成 finally 块调用 close()。Java 9 的语法糖不改变字节码语义，只减少冗余声明。

可执行示例

import java.io.*;

public class TryWithResourcesDemo {
    public static void main(String[] args) throws IOException {
        // Java 7/8 写法：必须在 try 中重新声明
        InputStream is1 = new FileInputStream("data.txt");
        try (InputStream copy = is1) {   // 多余的重新声明
            System.out.println("Read: " + copy.read());
        }

        // Java 9 写法：直接引用外部 effectively-final 变量
        final InputStream is2 = new FileInputStream("data.txt");
        try (is2) {
            System.out.println("Read: " + is2.read());
        } // is2 自动关闭

        // 多个资源
        final InputStream in = new FileInputStream("in.txt");
        final OutputStream out = new FileOutputStream("out.txt");
        try (in; out) {
            in.transferTo(out);
        } // in 和 out 都自动关闭

        // 混合：外部变量 + try 中声明
        final InputStream base = new FileInputStream("base.txt");
        try (base; BufferedReader br = new BufferedReader(new InputStreamReader(base))) {
            System.out.println(br.readLine());
        }
    }
}

1.4 钻石操作符 (<>) 扩展

Java 8 中匿名内部类不能用 <>，因为类型推断在匿名类上下文中不可靠。Java 9 放宽了这个限制。
只要推断的类型是「可表示的（denotable）」，就可以用 <>。不能用于函数式接口的 lambda（lambda 没有类型可推断）。

可执行示例

import java.util.*;

public class DiamondDemo {
    public static void main(String[] args) {
        // Java 7+: 普通泛型实例化
        List<String> list1 = new ArrayList<>();

        // Java 9: 匿名内部类也可以用 <>
        List<String> list2 = new ArrayList<>() {
            @Override
            public boolean add(String s) {
                System.out.println("Adding: " + s);
                return super.add(s);
            }
        };
        list2.add("hello");
        list2.add("world");

        // 比较器示例
        Comparator<String> byLength = new Comparator<>() {
            @Override
            public int compare(String a, String b) {
                return Integer.compare(a.length(), b.length());
            }
        };
        System.out.println(byLength.compare("abc", "ab")); // 1
    }
}

1.5 @SafeVarargs 注解扩展 NEW

Java 泛型使用类型擦除，可变参数泛型（T...）会导致「堆污染（Heap Pollution）」——可变参数底层是 Object[]，可以往里放任何类型的对象。@SafeVarargs 是告诉编译器的承诺：这个方法不会对可变参数数组做危险操作。Java 8 中 @SafeVarargs 只能用在 static 和 final 方法上，但 private 方法同样不可覆盖，也应该能用。Java 9 放宽了这个限制。
@SafeVarargs 是编译期的「抑制警告」注解。它不改变字节码，只影响 javac 是否发出 unchecked 警告。Java 9 允许在 private 实例方法上使用，因为这些方法不能被覆盖，安全性可保证。

可执行示例

import java.util.*;

public class SafeVarargsDemo {

    // Java 8 写法：final 方法上用 @SafeVarargs
    @SafeVarargs
    final <T> List<T> listOfFinal(T... elements) {
        return new ArrayList<>(Arrays.asList(elements));
    }

    // Java 9 写法：private 实例方法上用 @SafeVarargs
    @SafeVarargs
    private <T> List<T> listOfPrivate(T... elements) {
        return new ArrayList<>(Arrays.asList(elements));
    }

    public static void main(String[] args) {
        SafeVarargsDemo demo = new SafeVarargsDemo();

        List<String> l1 = demo.listOfFinal("a", "b", "c");
        System.out.println("final method: " + l1);

        List<Integer> l2 = demo.listOfPrivate(1, 2, 3);
        System.out.println("private method: " + l2);

        // 演示堆污染风险
        List<String> polluted = demo.unsafeList("hello", "world");
        System.out.println("unsafe list: " + polluted);
    }

    // 这个方法会产生 unchecked 警告，演示堆污染风险
    @SuppressWarnings("unchecked")
    <T> List<T> unsafeList(T... elements) {
        Object[] arr = elements;   // 可变参数底层是 Object[]
        arr[0] = 42;               // 堆污染：把 Integer 放进 String[]
        return (List<T>) Arrays.asList(elements);
    }
}

二、核心 API 与类库增强

2.1 集合工厂方法

Java 8 创建不可变集合很繁琐：Collections.unmodifiableList(Arrays.asList(...))。没有简洁的「创建包含元素的不可变集合」的方式。
List.of() 根据元素数量选择不同内部类：0 个元素返回 ListN.EMPTY_LIST，1 个返回 List12，2+ 返回 ListN。所有实现继承 AbstractImmutableList，修改方法抛 UnsupportedOperationException。不允许 null 元素。

可执行示例

import java.util.*;
import java.util.stream.*;

public class CollectionFactoryDemo {
    public static void main(String[] args) {
        // List.of
        List<String> list = List.of("apple", "banana", "cherry");
        System.out.println(list);

        // Set.of（重复元素抛 IllegalArgumentException）
        Set<Integer> set = Set.of(1, 2, 3, 4, 5);
        System.out.println(set);
        try {
            Set.of(1, 2, 2);
        } catch (IllegalArgumentException e) {
            System.out.println("Set.of 重复: " + e.getMessage());
        }

        // Map.of（最多 10 对）
        Map<String, Integer> map = Map.of(
            "apple", 1, "banana", 2, "cherry", 3
        );
        System.out.println(map);

        // Map.ofEntries（超过 10 对）
        Map<String, Integer> bigMap = Map.ofEntries(
            Map.entry("a", 1), Map.entry("b", 2),
            Map.entry("c", 3), Map.entry("d", 4),
            Map.entry("e", 5), Map.entry("f", 6),
            Map.entry("g", 7), Map.entry("h", 8),
            Map.entry("i", 9), Map.entry("j", 10),
            Map.entry("k", 11)
        );
        System.out.println("bigMap size: " + bigMap.size());

        // 不可变性验证
        try {
            list.add("date");
        } catch (UnsupportedOperationException e) {
            System.out.println("List 不可变");
        }

        // null 不允许
        try {
            List.of("a", null);
        } catch (NullPointerException e) {
            System.out.println("null 不允许");
        }

        // 与 Stream 结合
        List<Integer> squares = Stream.of(1, 2, 3, 4)
            .map(i -> i * i)
            .collect(Collectors.toUnmodifiableList());
        System.out.println("unmodifiable squares: " + squares);
    }
}

2.2 Stream API 增强

Java 8 的 Stream 缺少几个常用操作：① 没有「从头取到条件不满足」的方法；② Stream.of(null) 抛 NPE，无法安全处理；③ iterate 需要配合 limit 使用，不如 for 循环直观。
takeWhile/dropWhile 是有状态中间操作，维护「是否已停止」标志。ofNullable 返回 0 或 1 元素的 Stream。iterate 重载接受终止条件 Predicate。

可执行示例

import java.util.*;
import java.util.stream.*;

public class StreamEnhancements {
    public static void main(String[] args) {
        List<Integer> nums = List.of(45, 43, 76, 87, 42, 77, 90);

        // ===== takeWhile：从头取到第一个不满足 =====
        List<Integer> taken = nums.stream()
            .takeWhile(n -> n < 80)
            .collect(Collectors.toList());
        System.out.println("takeWhile < 80: " + taken);
        // [45, 43, 76]  — 遇到 87 停止

        // ===== dropWhile：跳过直到第一个不满足 =====
        List<Integer> dropped = nums.stream()
            .dropWhile(n -> n < 80)
            .collect(Collectors.toList());
        System.out.println("dropWhile < 80: " + dropped);
        // [87, 42, 77, 90]

        // 对比 filter：不依赖顺序
        List<Integer> filtered = nums.stream()
            .filter(n -> n < 80)
            .collect(Collectors.toList());
        System.out.println("filter < 80: " + filtered);
        // [45, 43, 76, 42, 77]

        // ===== ofNullable =====
        String maybeNull = null;
        System.out.println("ofNullable(null): " + Stream.ofNullable(maybeNull).count()); // 0
        System.out.println("ofNullable(hello): " + Stream.ofNullable("hello").count()); // 1

        try {
            Stream.of((Object) null);
        } catch (NullPointerException e) {
            System.out.println("Stream.of(null) 抛 NPE");
        }

        // ===== iterate 重载 =====
        // Java 8 写法：需要 limit
        List<Integer> oldWay = Stream.iterate(1, i -> i + 1)
            .limit(5)
            .collect(Collectors.toList());
        System.out.println("iterate+limit: " + oldWay); // [1,2,3,4,5]

        // Java 9 写法：直接指定终止条件
        List<Integer> newWay = Stream.iterate(1, i -> i <= 5, i -> i + 1)
            .collect(Collectors.toList());
        System.out.println("iterate with predicate: " + newWay); // [1,2,3,4,5]

        Stream.iterate(0, i -> i < 10, i -> i + 2)
            .forEach(i -> System.out.print(i + " ")); // 0 2 4 6 8
        System.out.println();
    }
}

2.3 Optional 类增强

Java 8 的 Optional 缺少几个常用操作：① 无法转为 Stream 参与流水线；② 没有「有值做什么，无值做什么」的一体化 API；③ 无法链式提供备选 Optional。
stream() 把 Optional 转为 0 或 1 元素 Stream；ifPresentOrElse() 接受两个 Consumer；or() 接受 Supplier<Optional>，延迟计算备选。

可执行示例

import java.util.*;
import java.util.stream.*;

public class OptionalEnhancements {
    public static void main(String[] args) {
        // ===== stream() =====
        Optional<String> opt = Optional.of("hello");
        List<String> fromOpt = opt.stream()
            .map(String::toUpperCase)
            .collect(Collectors.toList());
        System.out.println("stream(): " + fromOpt); // [HELLO]

        System.out.println("empty stream count: " + Optional.empty().stream().count()); // 0

        // ===== ifPresentOrElse =====
        Optional<String> present = Optional.of("value");
        present.ifPresentOrElse(
            v -> System.out.println("Found: " + v),
            () -> System.out.println("Not found")
        );

        Optional<String> empty = Optional.empty();
        empty.ifPresentOrElse(
            v -> System.out.println("Found: " + v),
            () -> System.out.println("Not found")
        );

        // ===== or() 链式备选 =====
        Optional<String> result = Optional.<String>empty()
            .or(() -> Optional.of("fallback"))
            .or(() -> Optional.of("never reached"));
        System.out.println("or(): " + result.get()); // fallback

        // or 是延迟的
        Optional<String> lazy = Optional.of("first");
        lazy.or(() -> {
            System.out.println("这个不会执行");
            return Optional.of("second");
        });
        System.out.println("lazy or: " + lazy.get()); // first

        // 组合用法
        Optional<String> config = Optional.empty();
        String value = config
            .or(() -> Optional.of("default"))
            .stream()
            .findFirst()
            .orElse("none");
        System.out.println("composed: " + value); // default
    }
}

2.4 全新 HTTP Client API

HttpURLConnection 老旧难用：API 不友好、不支持 HTTP/2、不支持 WebSocket。第三方库（OkHttp、Apache HttpClient）不是标准库。Java 9 引入官方 HTTP Client（incubator 模块 jdk.incubator.http），Java 11 正式化。
HttpClient 不可变、可复用。使用 Flow API（Reactive Streams）实现响应体的背压（backpressure）控制。BodyHandlers 决定响应体如何处理：字符串、文件、字节流、Publisher。

可执行示例

// 注意：Java 9 中包名是 jdk.incubator.http，Java 11 是 java.net.http
// 编译时需要 --add-modules jdk.incubator.http

import jdk.incubator.http.*;
import java.net.URI;
import java.time.Duration;
import java.util.concurrent.CompletableFuture;

public class HttpClientDemo {
    public static void main(String[] args) throws Exception {
        // 构建 Client（不可变、可复用）
        HttpClient client = HttpClient.newBuilder()
            .version(HttpClient.Version.HTTP_2)
            .connectTimeout(Duration.ofSeconds(10))
            .followRedirects(HttpClient.Redirect.NORMAL)
            .build();

        // ===== 同步 GET =====
        HttpRequest request = HttpRequest.newBuilder()
            .uri(URI.create("https://httpbin.org/get"))
            .timeout(Duration.ofSeconds(10))
            .header("Accept", "application/json")
            .GET()
            .build();

        HttpResponse<String> response = client.send(
            request, HttpResponse.BodyHandler.asString()
        );
        System.out.println("Status: " + response.statusCode());
        System.out.println("Body length: " + response.body().length());

        // ===== 异步 GET =====
        CompletableFuture<HttpResponse<String>> future =
            client.sendAsync(request, HttpResponse.BodyHandler.asString());
        future.thenAccept(resp -> {
            System.out.println("Async status: " + resp.statusCode());
        }).join();

        // ===== POST JSON =====
        HttpRequest postReq = HttpRequest.newBuilder()
            .uri(URI.create("https://httpbin.org/post"))
            .header("Content-Type", "application/json")
            .POST(HttpRequest.BodyProcessor.fromString(
                "{\"name\":\"Java9\"}"
            ))
            .build();

        HttpResponse<String> postResp = client.send(
            postReq, HttpResponse.BodyHandler.asString()
        );

2.5 进程 API 增强（ProcessHandle）

Java 9 之前，获取 PID 只能通过 hack：ManagementFactory.getRuntimeMXBean().getName() 返回 "pid@hostname" 然后 split。销毁进程只能用 Process.destroy()，无法获取进程树信息、CPU 使用率、启动时间。
ProcessHandle 是进程的轻量句柄，通过 Process.toHandle() 或 ProcessHandle.current() 获取。Info 内部类封装进程元数据。onExit() 返回 CompletableFuture 用于异步回调。

可执行示例

import java.util.concurrent.CompletableFuture;

public class ProcessHandleDemo {
    public static void main(String[] args) throws Exception {
        // ===== 当前进程信息 =====
        ProcessHandle current = ProcessHandle.current();
        ProcessHandle.Info info = current.info();

        System.out.println("PID: " + current.pid());
        info.command().ifPresent(cmd ->
            System.out.println("Command: " + cmd));
        info.commandLine().ifPresent(cl ->
            System.out.println("CommandLine: " + cl));
        info.startInstant().ifPresent(t ->
            System.out.println("Started: " + t));
        info.totalCpuDuration().ifPresent(d ->
            System.out.println("CPU: " + d));
        info.user().ifPresent(u ->
            System.out.println("User: " + u));

        // ===== 创建子进程并监控 =====
        Process p = new ProcessBuilder("sleep", "30").start();
        ProcessHandle handle = p.toHandle();
        System.out.println("\nChild PID: " + handle.pid());

        CompletableFuture<ProcessHandle> onExit = handle.onExit();
        onExit.thenAccept(h ->
            System.out.println("Process " + h.pid() + " exited")
        );
        System.out.println("State: " + handle.isAlive());

        // ===== 列出所有进程（前 5 个）=====
        System.out.println("\n=== All processes (top 5) ===");
        ProcessHandle.allProcesses()
            .filter(ProcessHandle::isAlive)
            .limit(5)
            .forEach(h -> h.info().command()
                .ifPresent(cmd ->
                    System.out.println(h.pid() + ": " + cmd)));

        // ===== 进程树 =====
        System.out.println("\n=== Process tree ===");
        current.children().forEach(child ->
            System.out.println("Child: " + child.pid()));

        // ===== 销毁 =====
        Thread.sleep(1000);
        handle.destroy();
        if (handle.isAlive()) {
            handle.destroyForcibly();
        }
    }
}

2.6 Stack-Walking API

Thread.getStackTrace() 和 new Throwable().getStackTrace() 一次性获取完整栈帧数组。但大多数场景只需要几个帧（如找到调用者类），获取完整栈既浪费性能又浪费内存。
StackWalker.walk() 传入函数，接收 Stream<StackFrame>——惰性流。JVM 只在需要时遍历帧。支持 RETAIN_CLASS_REFERENCE 等选项。

可执行示例

import java.lang.StackWalker;
import java.util.stream.Collectors;

public class StackWalkerDemo {
    public static void main(String[] args) {
        methodA();
    }

    static void methodA() { methodB(); }
    static void methodB() { methodC(); }

    static void methodC() {
        // 只获取前 3 个帧（高效）
        System.out.println("=== Top 3 frames ===");
        StackWalker.getInstance()
            .walk(frames -> frames
                .limit(3)
                .map(f -> f.getClassName() + "." + f.getMethodName()
                    + ":" + f.getLineNumber())
                .collect(Collectors.toList())
            )
            .forEach(System.out::println);

        // 获取调用者类（最常用场景）
        System.out.println("\n=== Caller class ===");
        Class<?> caller = StackWalker.getInstance(
            StackWalker.Option.RETAIN_CLASS_REFERENCE
        ).getCallerClass();
        System.out.println("Caller: " + caller.getName());

        // 条件过滤
        System.out.println("\n=== First frame from StackWalkerDemo ===");
        StackWalker.getInstance()
            .walk(frames -> frames
                .filter(f -> f.getClassName().endsWith("StackWalkerDemo"))
                .findFirst()
            )
            .ifPresent(f -> System.out.println(f.getClassName() + "." + f.getMethodName()));

        // 完整栈数量
        long count = StackWalker.getInstance().walk(frames -> frames.count());
        System.out.println("Total frames: " + count);
    }
}

2.7 VarHandle

sun.misc.Unsafe 提供低层内存操作，但它是私有 API，随时可能移除。AtomicInteger 等原子类功能有限。VarHandle 是官方替代方案，提供类型安全的变量访问和原子操作。
VarHandle 通过 MethodHandles.lookup().findVarHandle() 获取。首次查找后生成最优调用路径，性能接近直接字段访问。支持内存序控制：setRelease/getAcquire/compareAndSet/getAndAdd 等。

可执行示例

import java.lang.invoke.MethodHandles;
import java.lang.invoke.VarHandle;

public class VarHandleDemo {
    private volatile int x;
    private static final VarHandle X;

    static {
        try {
            X = MethodHandles.lookup()
                .findVarHandle(VarHandleDemo.class, "x", int.class);
        } catch (Exception e) {
            throw new Error(e);
        }
    }

    public static void main(String[] args) {
        VarHandleDemo demo = new VarHandleDemo();

        X.set(demo, 10);
        System.out.println("set: " + X.get(demo)); // 10

        boolean success = X.compareAndSet(demo, 10, 20);
        System.out.println("CAS 10→20: " + success + ", value=" + X.get(demo));

        int old = (int) X.getAndAdd(demo, 5);
        System.out.println("getAndAdd(5): old=" + old + ", new=" + X.get(demo));

        X.setVolatile(demo, 100);
        int val = (int) X.getVolatile(demo);
        System.out.println("volatile access: " + val);

        X.setRelease(demo, 200);
        int acquired = (int) X.getAcquire(demo);
        System.out.println("acquire/release: " + acquired);
    }
}

2.8 多分辨率图像 API NEW

在不同 DPI 的屏幕上（普通屏、Retina 屏、4K 屏），同一张图片需要不同分辨率的版本才能显示清晰。Java 9 之前，开发者需要自己管理多份图片。Java 9 引入 java.awt.image.MultiResolutionImage，把多个分辨率的图像封装成一个逻辑图像，由系统根据显示环境自动选择合适的版本。
MultiResolutionImage 是一个接口，核心方法 getResolutionVariant(width, height) 根据目标尺寸返回最合适的图像变体。BaseMultiResolutionImage 是默认实现。它与 java.awt.Graphics 的渲染管线集成：当绘制到高 DPI 设备时自动选择高分辨率变体。

可执行示例

import java.awt.*;
import java.awt.image.*;
import javax.swing.*;

        // Image img2x = ImageIO.read(new File("icon@2x.png"));

        g.fillRect(0, 0, w, h);
        g.dispose();

    }

2.9 @Deprecated 注解增强 NEW

Java 8 之前 @Deprecated 只是一个标记，无法表达「为什么废弃」「从哪个版本开始废弃」「未来是否会移除」。开发者看到 @Deprecated 时无法判断：这个 API 是暂时不推荐还是即将删除？是应该尽快迁移还是可以继续用？
Java 9 为 @Deprecated 增加两个属性：since（从哪个版本废弃）和 forRemoval（是否会在未来版本移除）。forRemoval=true 时 javac 会发出更强的警告。这两个属性让废弃决策从「模糊的标记」变成「可操作的信号」。

可执行示例

public class DeprecatedDemo {

    // 普通废弃：暂时不推荐，但不会移除
    @Deprecated(since = "9", forRemoval = false)
    public static void oldButUsable() {
        System.out.println("This is deprecated but still usable");
    }

    // 即将移除：应该尽快迁移
    @Deprecated(since = "9", forRemoval = true)
    public static void willBeRemoved() {
        System.out.println("This will be removed in a future version");
    }

    // 只有 since，默认 forRemoval=false
    @Deprecated(since = "9")
    public static void sinceOnly() {
        System.out.println("Deprecated since 9");
    }

    public static void newMethod() {
        System.out.println("Use this instead");
    }

    public static void main(String[] args) throws Exception {
        oldButUsable();
        willBeRemoved();
        sinceOnly();
        newMethod();

        // 通过反射读取注解属性
        System.out.println("\n=== 反射读取 @Deprecated 属性 ===");
        readDeprecatedInfo("oldButUsable");
        readDeprecatedInfo("willBeRemoved");
        readDeprecatedInfo("sinceOnly");
        readDeprecatedInfo("newMethod");
    }

    static void readDeprecatedInfo(String methodName) throws Exception {
        java.lang.reflect.Method m = DeprecatedDemo.class
            .getMethod(methodName);
        Deprecated d = m.getAnnotation(Deprecated.class);
        System.out.println("\nMethod: " + methodName);
        if (d == null) {
            System.out.println("  Not deprecated");
            return;
        }
        System.out.println("  since: " + d.since());
        System.out.println("  forRemoval: " + d.forRemoval());
    }
}

3.2 序列化过滤（Serialization Filtering）

Java 反序列化是最著名的安全漏洞来源（Apache Commons Collections、WebLogic、Jenkins 等）。攻击者可以构造恶意序列化数据，在反序列化时执行任意代码。Java 9 引入 ObjectInputFilter 机制，允许在反序列化时白名单/黑名单过滤类。
ObjectInputFilter 在反序列化每个类时被调用，返回 ALLOWED / REJECTED / UNDECIDED。可以设置 JVM 级全局过滤器、线程级过滤器、或流级过滤器。

可执行示例

import java.io.*;
import java.util.*;

public class SerializationFilterDemo {

    static class SafeData implements Serializable {
        private static final long serialVersionUID = 1L;
        String value;
        SafeData(String v) { this.value = v; }
        @Override public String toString() { return "SafeData{" + value + "}"; }
    }

    public static void main(String[] args) throws Exception {
        // ===== 1. 设置 JVM 级全局过滤器（白名单模式）=====
        ObjectInputFilter globalFilter = ObjectInputFilter.Config.createFilter(
            "com.example.SerializationFilterDemo$SafeData;" +
            "java.lang.*;" +
            "java.util.*;" +
            "!*"
        );
        ObjectInputFilter.Config.setSerialFilter(globalFilter);

        System.out.println("Global filter set: " +
            ObjectInputFilter.Config.getSerialFilter());

        // ===== 2. 序列化安全对象 =====
        SafeData data = new SafeData("hello");
        byte[] bytes = serialize(data);
        System.out.println("Serialized: " + bytes.length + " bytes");

        // ===== 3. 反序列化（通过过滤器）=====
        Object restored = deserialize(bytes);
        System.out.println("Restored: " + restored);

        // ===== 4. 流级过滤器 =====
        System.out.println("\n=== Stream-level filter ===");
        byte[] data2 = serialize(new ArrayList<>(List.of("a", "b")));

        try (ObjectInputStream ois = new ObjectInputStream(
                new ByteArrayInputStream(data2))) {
            ois.setObjectInputFilter(info -> {
                Class<?> clazz = info.serialClass();
                if (clazz == null) return ObjectInputFilter.Status.UNDECIDED;
                String name = clazz.getName();
                System.out.println("  Filter check: " + name);
                if (name.startsWith("java.util.")) {
                    return ObjectInputFilter.Status.ALLOWED;
                }
                return ObjectInputFilter.Status.REJECTED;
            });

            Object obj = ois.readObject();
            System.out.println("Deserialized: " + obj);
        }

        // ===== 5. 拒绝场景 =====
        System.out.println("\n=== Reject demo ===");
        try (ObjectInputStream ois = new ObjectInputStream(
                new ByteArrayInputStream(bytes))) {
            ois.setObjectInputFilter(info -> ObjectInputFilter.Status.REJECTED);
            ois.readObject();
        } catch (InvalidClassException e) {
            System.out.println("Rejected: " + e.getMessage());
        }

        // ===== 6. 启动参数方式 =====
        System.out.println("\n=== JVM 启动参数方式 ===");
        System.out.println("java -Djdk.serialFilter='com.example.*;java.base/*;!*' MyApp");
    }

    static byte[] serialize(Object obj) throws IOException {
        try (ByteArrayOutputStream baos = new ByteArrayOutputStream();
             ObjectOutputStream oos = new ObjectOutputStream(baos)) {
            oos.writeObject(obj);
            return baos.toByteArray();
        }
    }

    static Object deserialize(byte[] data) throws Exception {
        try (ObjectInputStream ois = new ObjectInputStream(
                new ByteArrayInputStream(data))) {
            return ois.readObject();
        }
    }
}

3.3 统一 JVM 日志

Java 9 之前，不同 JVM 组件使用不同日志机制：GC 用 -Xloggc，类加载用 -XX:+TraceClassLoading，JIT 用 -XX:+PrintCompilation。格式不统一，无法集中过滤。
引入 -Xlog 选项，用标签系统统一所有 JVM 日志。标签如 gc、class、os、safepoint、exceptions。支持按标签、级别、输出目标过滤。

可执行示例

# 1. 基础用法：GC 日志到文件
java -Xlog:gc*:file=gc.log:time,uptime,level,tags -jar app.jar

# 2. 选择性输出：只输出 gc 和 class loading 的 info 级别
java -Xlog:gc+class=info -jar app.jar

# 3. 输出到 stdout
java -Xlog:gc:stdout -jar app.jar

# 4. 按标签过滤 + 按级别过滤
java -Xlog:gc*=debug:file=gc-debug.log -jar app.jar

# 5. 多标签组合
java -Xlog:gc+heap=debug,gc+ergo=debug -jar app.jar

# 6. 查看所有可用标签
java -Xlog:help

# 7. 输出示例（GC + 类加载）
java -Xlog:gc,class+load=info -jar app.jar

3.5 CompletableFuture 改进

Java 8 的 CompletableFuture 缺少几个实用功能：① 没有超时控制；② 没有延迟执行器；③ 不能与 ProcessHandle 联动。Java 9 补充了这些。
新增 delayedExecutor()、orTimeout()、completeOnTimeout()，以及支持 ProcessHandle.onExit() 返回的 CompletableFuture。

可执行示例

import java.util.concurrent.*;

public class CompletableFutureEnhancement {
    public static void main(String[] args) throws Exception {

        // ===== 1. orTimeout：超时后抛 TimeoutException =====
        System.out.println("=== orTimeout ===");
        CompletableFuture<String> slow = CompletableFuture.supplyAsync(() -> {
            try { Thread.sleep(5000); } catch (InterruptedException e) {}
            return "done";
        });
        try {
            slow.orTimeout(1, TimeUnit.SECONDS).join();
        } catch (CompletionException e) {
            System.out.println("Timeout: " + e.getCause().getClass().getSimpleName());
        }

        // ===== 2. completeOnTimeout：超时后用默认值 =====
        System.out.println("\n=== completeOnTimeout ===");
        CompletableFuture<String> withDefault =
            CompletableFuture.supplyAsync(() -> {
                try { Thread.sleep(5000); } catch (InterruptedException e) {}
                return "real";
            }).completeOnTimeout("default", 1, TimeUnit.SECONDS);
        System.out.println("Result: " + withDefault.join()); // default

        // ===== 3. delayedExecutor：延迟执行器 =====
        System.out.println("\n=== delayedExecutor ===");
        Executor delayed = CompletableFuture.delayedExecutor(
            1, TimeUnit.SECONDS
        );
        long start = System.currentTimeMillis();
        CompletableFuture<String> delayedTask = CompletableFuture.supplyAsync(
            () -> "delayed result",
            delayed
        );
        System.out.println("Result: " + delayedTask.join()
            + " (after " + (System.currentTimeMillis() - start) + "ms)");

        // 带自定义线程池的延迟执行器
        ExecutorService pool = Executors.newFixedThreadPool(2);
        Executor delayedOnPool = CompletableFuture.delayedExecutor(
            500, TimeUnit.MILLISECONDS, pool
        );
        CompletableFuture.supplyAsync(() -> "on pool", delayedOnPool).join();
        pool.shutdown();

        // ===== 4. 与 ProcessHandle.onExit 联动 =====
        System.out.println("\n=== ProcessHandle.onExit ===");
        Process p = new ProcessBuilder("sleep", "2").start();
        ProcessHandle handle = p.toHandle();

        CompletableFuture<ProcessHandle> onExit = handle.onExit();
        onExit.thenAccept(h ->
            System.out.println("Process " + h.pid() + " exited")
        );
        System.out.println("Waiting for process...");
        onExit.join();

        // ===== 5. 组合使用 =====
        System.out.println("\n=== 组合使用 ===");
        CompletableFuture<String> combo = CompletableFuture
            .supplyAsync(() -> {
                try { Thread.sleep(3000); } catch (InterruptedException e) {}
                return "slow";
            })
            .completeOnTimeout("timeout-fallback", 1, TimeUnit.SECONDS)
            .thenApply(s -> "final: " + s);
        System.out.println(combo.join()); // final: timeout-fallback

        System.out.println("\n=== 完成 ===");
    }
}
