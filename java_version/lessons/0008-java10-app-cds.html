L1 · 概念层：CDS 的扩展

类数据共享（CDS）从 JDK 5 就存在，但仅限于引导类加载器加载的系统类。AppCDS 将 CDS 扩展到三个类加载器：内置系统类加载器（app class loader）、内置平台类加载器和自定义类加载器，使应用程序类也能从共享归档中加载[reference:10]。

核心价值

收益原理
缩短启动时间类元数据从预处理的归档文件中 mmap 到内存，避免解析 class 文件的 CPU 开销
减少内存占用多个 JVM 进程共享同一份归档文件的物理内存（mmap 的只读映射天然支持进程间共享）
容器化友好启动时间缩短 10%~20%，适合 K8s 等容器编排场景
容器化部署中的 AppCDS

在 K8s 中，多个 Pod 运行同一 Java 镜像时，AppCDS 归档文件被 mmap 到各进程地址空间。物理内存只在宿主机上保留一份，显著降低内存开销。配合 -XX:SharedArchiveFile 指向镜像内的只读归档路径，是微服务启动优化的标准手段。

L2 · 原理层：CDS 工作流程

三步流程（Java 10 原始方式）

flowchart LR A["1. 收集类列表
-XX:DumpLoadedClassList"] --> B["2. 生成归档
-Xshare:dump"] B --> C["3. 使用归档
-Xshare:on"] C --> D{归档版本匹配?} D -->|是| E[mmap 加载类元数据] D -->|否| F[回退到文件系统加载] 
# 步骤 1：收集类列表
java -Xshare:off -XX:+UseAppCDS \
     -XX:DumpLoadedClassList=hello.lst \
     -cp hello.jar HelloWorld

# 步骤 2：生成归档
java -Xshare:dump -XX:+UseAppCDS \
     -XX:SharedClassListFile=hello.lst \
     -XX:SharedArchiveFile=hello.jsa \
     -cp hello.jar

# 步骤 3：使用归档
java -Xshare:on -XX:+UseAppCDS \
     -XX:SharedArchiveFile=hello.jsa \
     -cp hello.jar HelloWorld
版本匹配的硬约束

CDS 归档文件与 JDK 版本严格绑定。升级 JDK 后必须重新生成归档，否则 JVM 会静默回退到文件系统加载——不会报错，但也没有加速效果[reference:11]。这是生产环境中最容易踩的坑。

InstanceKlass* ClassLoader::load_class(const char* name, ...) {
    if (UseSharedSpaces) {
        // 尝试从共享归档中加载
        InstanceKlass* k = SystemDictionary::find_shared_class(name);
        if (k != NULL) {
            return k;  // 命中归档，直接返回

    }
    // 未命中，从文件系统加载
    return load_class_from_file(name, ...);
}

L4 · 边界层：局限与演进

局限说明
JDK 版本绑定归档文件必须在相同 JDK 版本下生成和使用
类路径一致性生成和使用归档时的 -cp 必须一致
动态代理类运行时生成的类（如动态代理）无法被归档
三步流程繁琐Java 10 中需要三个步骤，Java 13 简化为两步，Java 19 支持自动生成

L5 · 面试层

Q1: AppCDS 为什么能减少内存占用？

因为归档文件被 mmap 为只读映射。操作系统对同一文件的只读 mmap 在不同进程间共享物理页——多个 JVM 进程看到的归档内容映射到同一块物理内存。类元数据只在内存中保留一份，而非每个进程一份。

关键点：共享的是物理内存页，不是虚拟地址空间。
Q2: 追问 — 如果 JDK 升级了，AppCDS 归档会怎样？

JVM 在启动时会检查归档文件的 JDK 版本。如果不匹配，会静默忽略归档，回退到文件系统加载类。不会报错，但也不会有加速效果。这是生产环境中的隐形坑——部署新 JDK 后如果忘记重新生成归档，启动优化会悄悄失效。

关键点：静默回退是设计选择（保证兼容性），但需要监控启动时间来发现。
Q3: 追问 — 画出 AppCDS 类加载的伪代码。
function loadClass(className, classLoader):
    if UseSharedSpaces:
        sharedClass = SystemDictionary.findSharedClass(className, classLoader)
        if sharedClass != null:
            return sharedClass  // 命中归档

    // 未命中，正常从文件系统加载
    return loadFromFileSystem(className, classLoader)

核心判断：先查共享归档，未命中再走常规加载。

关键点：归档查找在类加载路径的最前端，零成本（一次哈希查找）。
