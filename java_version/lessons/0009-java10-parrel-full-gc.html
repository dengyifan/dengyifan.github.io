L1 · 概念层：解决什么问题

G1 从 Java 9 起成为默认 GC，但它的 Full GC 有一个致命缺陷：单线程执行。当并发模式失败、晋升失败或疏散失败触发 Full GC 时，整个 JVM 会用一个线程执行 Mark-Sweep-Compact 算法，在多核机器上完全浪费 CPU 资源[reference:12]。

JEP 307 将 Full GC 改为并行执行，利用多核 CPU 缩短最坏情况下的 STW 暂停时间。

生产环境的真实影响

Bazel 项目在 JDK 9 时代曾报告：使用 G1 后 Java 构建性能回退约 30%，原因是 G1 的 Full GC 单线程瓶颈。升级到 Java 10 后，并行 Full GC 解决了这个问题，Bazel 重新启用了 G1。

L2 · 原理层：Full GC 的四个阶段

flowchart LR A[Phase 1
标记存活对象] --> B[Phase 2
准备压缩] B --> C[Phase 3
调整指针] C --> D[Phase 4
执行压缩]

四个阶段全部通过 G1FullCollector::run_task() 使用工作线程组并行执行：

// 并行执行任务的核心方法
void G1FullCollector::run_task(AbstractGangTask* task) {
    G1CollectedHeap::heap()->workers()
        ->run_task(task, _num_workers);
}

_num_workers 来自 workers()->active_workers()，即当前活跃的 GC 工作线程数，默认与 CPU 核数相关[reference:14]。

并行化的粒度

阶段并行化策略
Phase 1: 标记按 Region 分区并行标记，各线程处理不同的 Region 集合
Phase 2: 准备压缩并行计算每个 Region 的压缩目标位置
Phase 3: 调整指针并行遍历对象引用，调整指向新位置的指针
Phase 4: 压缩并行移动对象到压缩后的位置

与串行版本的对比

// Java 9 · G1SerialFullCollector（单线程）
G1SerialFullCollector serial(scope, ref_processor_stw());
serial.prepare_collection();
serial.collect();
serial.complete_collection();

// Java 10 · G1FullCollector（并行）
G1FullCollector collector(scope, ref_processor_stw(),
    concurrent_mark()->next_mark_bitmap(),
    workers()->active_workers());
collector.prepare_collection();
collector.collect();
collector.complete_collection();

改动核心：新增了 mark_bitmap 和工作线程数入参，标记阶段不再使用 STW 引用处理器的单线程发现，而是使用并发标记的 next_mark_bitmap 进行并行标记[reference:15]。

监控建议

使用 -Xlog:gc* 开启 GC 日志，观察 Full GC 的 Pause 时间。在 Java 10 之前，Full GC 暂停时间可能达到秒级；Java 10 后，多核机器上的暂停时间应显著下降。如果 Full GC 频繁触发，需要检查是否存在内存泄漏或堆大小配置不当。

L5 · 面试层

Q1: G1 的 Full GC 在 Java 10 之前为什么是单线程的？

历史原因。G1 最初是从 CMS 和 Parallel GC 的代码基础演进而来的。Parallel GC 的 Full GC 早已并行化，但 G1 在实现 Full GC 时选择了更简单的串行算法——因为 Full GC 本身是「最坏情况」的兜底路径，G1 的设计假设是尽量避免触发 Full GC。然而实际生产中 Full GC 仍然会发生，单线程成为严重瓶颈。

关键点：不是设计失误，而是优先级权衡——Full GC 优化被推迟了。
Q2: 追问 — G1 Full GC 并行化的核心改动是什么？

核心是引入 G1FullCollector 替代 G1SerialFullCollector，将四个阶段（标记、准备压缩、调整指针、压缩）全部改为通过 WorkGang 并行执行。关键入参增加了 mark_bitmap（复用并发标记的 bitmap）和 active_workers（工作线程数）。

关键点：不是简单地把循环改成并行，而是重新设计了任务划分和数据共享。
Q3: 追问 — 画出并行 Full GC 的阶段伪代码。
function fullGC():
    collector = new G1FullCollector(active_workers)
    collector.prepare_collection()

    // Phase 1: 并行标记
    workers.runTask(G1FullGCMarkTask)

    // Phase 2: 并行准备压缩
    workers.runTask(G1FullGCPrepareTask)

    // Phase 3: 并行调整指针
    workers.runTask(G1FullGCAdjustTask)

    // Phase 4: 并行压缩
    workers.runTask(G1FullGCCompactTask)

    collector.complete_collection()
关键点：四个阶段串行，每个阶段内部并行——这是典型的「分阶段并行」设计。
