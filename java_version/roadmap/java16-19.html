16.1 Records 正式（JEP 395）

14（JEP 359）、15（JEP 384）两次预览后在 16 转正：编译期生成 equals/hashCode/toString 与全参构造器、final 类、私有 final 字段 + 访问器（不是 getter）。

import java.lang.reflect.Modifier;
public class Rec16 {
  record Person(String name, int age) {}
  public static void main(String[] a) {
    var p = new Person("ann", 3);
    System.out.println(Modifier.isFinal(Person.class.getModifiers()) + " " + p);
    System.out.println(p.equals(new Person("ann", 3)) + " " + p.name() + "/" + p.age());
  }
}
// 运行输出：
// true Person[name=ann, age=3]
// true ann/3

✅ 实测通过（JDK 25）。要点：Person 隐式 final；equals 按组件逐一比较（值语义）；toString 是 类名[组件=值, …]。

16.2 Pattern Matching for instanceof 转正（JEP 394）

14 预览、16 转正：模式变量的作用域是流敏感的——只有 instanceof 成立的分支里变量才在作用域内，省掉强转与重复取值。

public class PM16 {
  static String describe(Object o) {
    if (o instanceof String s && s.length() > 3) return "long:" + s;
    if (o instanceof Number n) return "num:" + n.intValue();
    return "other";
  }
  public static void main(String[] a) {
    System.out.println(describe("hello") + " " + describe(42) + " " + describe(true));
    Object o = "abc";
    if (o instanceof String s) System.out.println("matched:" + s.toUpperCase());
  }
}
// 运行输出：
// long:hello num:42 other
// matched:ABC

✅ 实测通过（JDK 25）。要点：&& 右侧才能用左侧声明的模式变量（这正是守卫在 instanceof 上的写法）；Number n 能接住装箱后的 Integer。

16.3 Sealed Classes 第二次预览（JEP 397）

15（JEP 360）首次预览，16 第二次预览把 sealed/non-sealed/permits 从普通标识符改为上下文关键字（可作方法/字段名）；17（JEP 409）转正。受控继承让编译器能做穷尽性检查。

public class Sealed16 {
  public sealed interface Shape permits Circle, Square, Blob {}
  public static final record Circle(double r) implements Shape {}
  public static record Square(double s) implements Shape {}
  public static non-sealed class Blob implements Shape {}
  public static class CustomBlob extends Blob {}
  public static void main(String[] a) {
    Shape s = new Circle(2.0);
    String d = switch (s) {
      case Circle c -> "circle " + c.r();
      case Square q -> "square " + q.s();
      case Blob b -> "blob";
    };
    System.out.println(d + " " + (new CustomBlob() instanceof Blob));
  }
}
// 运行输出：
// circle 2.0 true

✅ 实测通过（JDK 25）。要点：三种子类约束 final（叶子）/ sealed（继续受控）/ non-sealed（放开继承，CustomBlob 才能继承 Blob）；switch 因 Shape 受控可省 default。⚠️ 内部类声明必须可静态（这里用 static），否则编译报「no enclosing instance of type」。

16.4 Pattern Matching for switch（⚠️ 素材勘误，见上方注）

版本忠实写法（属于 JDK 17 预览，16 的 javac 不认；17/18 的守卫写作 p && e）：

// ❌ 未实测：JDK 17（JEP 406）预览写法，需 javac --enable-preview --release 17
Object o = "hi";
String s = switch (o) {
    case String str && str.length() > 1 -> "long string";   // guarded pattern：p && e
    case String str                    -> "str:" + str;
    case Integer i && i < 0            -> "neg int";
    case Integer i                     -> "int:" + i;
    case null                          -> "null";
    default                            -> "other";
};

JDK 25 等价写法（=21 转正形态，守卫已改成 when）见 17.2。

16.5 Unix-Domain Socket Channels（JEP 380）

本地进程间通信用 AF_UNIX 套接字，比 TCP 回环少一层网络栈、也不占端口号（文件路径即地址）。

import java.net.StandardProtocolFamily;
import java.net.UnixDomainSocketAddress;
import java.nio.ByteBuffer;
import java.nio.channels.ServerSocketChannel;
import java.nio.channels.SocketChannel;
import java.nio.file.Files;
public class Unix16 {
  public static void main(String[] a) throws Exception {
    var sock = Files.createTempFile("uds", ".sock");
    Files.delete(sock);
    var addr = UnixDomainSocketAddress.of(sock);
    try (var server = ServerSocketChannel.open(StandardProtocolFamily.UNIX)) {
      server.bind(addr);
      var t = new Thread(() -> {
        try (var ch = server.accept()) {
          var buf = ByteBuffer.allocate(64);
          ch.read(buf);
          buf.flip();
          ch.write(buf);
        } catch (Exception e) { throw new RuntimeException(e); }
      });
      t.start();
      try (var client = SocketChannel.open(StandardProtocolFamily.UNIX)) {
        client.connect(addr);
        client.write(ByteBuffer.wrap("ping".getBytes()));
        var buf = ByteBuffer.allocate(64);
        int n = client.read(buf);
        System.out.println(new String(buf.array(), 0, n));
      }
      t.join();
    }
    System.out.println("socketFile=" + Files.exists(sock));
    Files.deleteIfExists(sock);
  }
}
// 运行输出：
// ping
// socketFile=true

✅ 实测通过（JDK 25 · macOS）。要点：地址是必须事先不存在的文件路径（bind 前要删掉 createTempFile 建出来的文件）；握手即回显，端口无关。

16.6 Stream.toList()

比 collect(Collectors.toList()) 更短，且不可变、允许 null 元素；源码 @since 16（无对应 JEP）。

import java.util.List;
public class StreamTo16 {
  public static void main(String[] a) {
    var l = List.of(3, 1, 2).stream().sorted().toList();
    System.out.println(l);
    try { l.add(9); } catch (UnsupportedOperationException e) { System.out.println("unmodifiable"); }
  }
}
// 运行输出：
// [1, 2, 3]
// unmodifiable

✅ 实测通过（JDK 25）。与 collect(Collectors.toUnmodifiableList()) 等价；与 collect(toList()) 的区别是后者可变。

16.7 Stream.mapMulti()

「一进多出」的映射：回调里调用 emit 几次就产生几个元素——比 flatMap 少一次嵌套流构造（源码 @since 16）。

import java.util.List;
import java.util.stream.Stream;
public class MapMulti16 {
  public static void main(String[] a) {
    var words = Stream.of("a,b", "", "c").<String>mapMulti((s, emit) -> {
      if (s.isEmpty()) emit.accept("(empty)");
      else for (var p : s.split(",")) emit.accept(p);
    }).toList();
    System.out.println(words);
    var flat = Stream.of(List.of(1, 2), List.of(3)).<Integer>mapMulti((l, emit) -> l.forEach(emit)).toList();
    System.out.println(flat);
  }
}
// 运行输出：
// [a, b, (empty), c]
// [1, 2, 3]

✅ 实测通过（JDK 25）。要点：显式写 .<String>mapMulti 指定泛型参数（lambda 里用不到流类型时编译器推不出来）；与 flatMap 不同，emit 是消费回调，可 0 次、多次。

16.8 Vector API（JEP 338 · Incubator）

SIMD 向量化：把循环交给 IntVector 一次算 8 个 int（256 位）。注意 JEP 编号——16 的 Vector API 是 338，333 是 ZGC 成为生产特性。

import java.util.Arrays;
import jdk.incubator.vector.IntVector;
public class Vec16 {
  public static void main(String[] a) {
    var species = IntVector.SPECIES_256;
    var va = IntVector.fromArray(species, new int[]{1, 2, 3, 4, 5, 6, 7, 8}, 0);
    var vb = IntVector.fromArray(species, new int[]{10, 20, 30, 40, 50, 60, 70, 80}, 0);
    var out = new int[species.length()];
    va.add(vb).intoArray(out, 0);
    System.out.println(Arrays.toString(out));
    System.out.println("lanes=" + species.length());
  }
}
// 运行输出（stdout）：
// [11, 22, 33, 44, 55, 66, 77, 88]
// lanes=8
// （stderr 另打印孵化提示：WARNING: Using incubator modules: jdk.incubator.vector）

✅ 实测通过（JDK 25，javac/java 都带 --add-modules jdk.incubator.vector）。要点：孵化模块，包名与模块名都是 jdk.incubator.vector，API 随时会变；SPECIES_256 在本机给 8 条 int lane，逐 lane 的加法与标量循环结果一致（本示例不触发溢出差异）。

17.1 Sealed Classes 正式（JEP 409）

15/16 两次预览后转正，免预览开关。规则：被 sealed 修饰的类/接口的直接子类必须显式带 final、sealed、non-sealed 之一。

public class Sealed17 {
  public abstract static sealed class Vehicle permits Car, Bike, Scooter {}
  public static final class Car extends Vehicle {}
  public static final class Bike extends Vehicle {}
  public static non-sealed class Scooter extends Vehicle {}
  public static class ElectricScooter extends Scooter {}
  public static void main(String[] a) {
    Vehicle v = new ElectricScooter();
    System.out.println(v.getClass().getSimpleName());
    System.out.println(switch (v) {
      case Car c -> "car";
      case Bike b -> "bike";
      case Scooter s -> "scooter";
    });
  }
}
// 运行输出：
// ElectricScooter
// scooter

✅ 实测通过（JDK 25）。要点：子类与被许可类同文件可省 permits，跨文件/跨 jar 时必须写（编译器靠它做穷尽性推导）；non-sealed 之后的 ElectricScooter 不受控，所以 case Scooter s 要放在能覆盖它的位置。

17.2 Pattern Matching for switch 首次预览（JEP 406）

版本忠实写法（JDK 17 预览：守卫是 guarded pattern p && e，null 要显式 case null）：

// ❌ 未实测：JDK 17 预览写法（javac --enable-preview --release 17）
// JEP 406/420 都是 p && e；when 是 JDK 19 的 JEP 427 才引入的，25 上此写法编译不过
Object o = "hi";
String s = switch (o) {
    case String str && str.isEmpty() -> "empty-string";
    case String str                 -> "string:" + str;
    case Integer i && i < 0         -> "neg-int";
    case Integer i                  -> "int:" + i;
    case null                       -> "null";
    default                         -> "other";
};

JDK 25 等价写法（=21 转正 JEP 441 形态，免预览）：

public class SwitchPM17 {
  static String kind(Object o) {
    return switch (o) {
      case String s when s.isEmpty() -> "empty-string";
      case String s -> "string:" + s;
      case Integer i when i < 0 -> "neg-int";
      case Integer i -> "int:" + i;
      case null -> "null";
      default -> "other";
    };
  }
  public static void main(String[] a) {
    System.out.println(kind("") + "/" + kind("hi") + "/" + kind(-5) + "/" + kind(7));
    System.out.println(kind(null) + "/" + kind(3.14));
  }
}
// 运行输出：
// empty-string/string:hi/neg-int/int:7
// null/other

✅ 实测通过（JDK 25）。要点：case null 必须显式写，否则选择器为 null 直接 NPE；带守卫的标签要排在同类型无守卫标签之前（dominance 检查）；default 兜住未匹配类型（如 Double）。

勘误：when 守卫不是 17 的

素材写「17 支持 when 守卫」，时序不对：JEP 406（17）与 JEP 420（18）的守卫写作 p && e（JEP 420 正文甚至把 p when e 列为「备选方案」并明确否掉，理由是 && 无需新增上下文关键字）；case P when e 是 JDK 19 的 JEP 427 才改的，21 随 JEP 441 转正。示例按 25 现行写法给 ✅。

17.3 always-strict 浮点（JEP 306）

17 起 Java 语言在所有平台上都要求浮点按 IEEE-754 单步（strict）语义执行，strictfp 关键字保留但已无效果。此前在非 x86-SSE/扩展精度平台上结果可能与别处不同，是经典的跨机器行为漂移源。

public class Strict17 {
  strictfp static double calc(double a, double b) { return (a * b + 1.0) / 3.0; }
  public static void main(String[] a) {
    System.out.println(0.1 + 0.2);
    System.out.println(calc(0.1, 0.2));
    System.out.println("strictfp ok");
  }
}
// 运行输出：
// 0.30000000000000004
// 0.34
// strictfp ok

✅ 实测通过（JDK 25）。要点：strictfp 仍可编译（关键字不删，向后兼容），但语义已与普通方法一致；0.1 + 0.2 不等于 0.3 是二进制浮点表示的必然结果，JEP 306 保证它到处都是这个结果。

17.4 RandomGenerator / RandomGeneratorFactory（JEP 356）

统一随机数接口：Random 成为 RandomGenerator 的实现之一，新增 L128X1024MixRandom、Xoroshiro128PlusPlus 等更快/更长周期的算法，可按名字查工厂。

import java.util.random.RandomGenerator;
import java.util.random.RandomGeneratorFactory;
public class Rng17 {
  public static void main(String[] a) {
    var f = RandomGeneratorFactory.of("L128X1024MixRandom");
    RandomGenerator g1 = f.create(42);
    RandomGenerator g2 = f.create(42);
    System.out.println(f.name() + " bits=" + f.stateBits());
    System.out.println("same-seed-same-seq=" + (g1.nextLong() == g2.nextLong()));
    System.out.println("providers=" + RandomGeneratorFactory.all().count());
  }
}
// 运行输出：
// L128X1024MixRandom bits=1152
// same-seed-same-seq=true
// providers=13

✅ 实测通过（JDK 25）。要点：同种子同算法则序列一致（可复现实验）；providers=13 是 JDK 25 的实现数（17 起逐步增加，别硬记）；stateBits 是内部状态位宽，越大周期越长（2^1152 级）。

17.5 上下文特定反序列化过滤器（JEP 415）

JEP 290（16）的过滤器只能挂在整条流上，415 把它下放到每个反序列化入口（readObject/readUnshared）：可在一次读取里临时换过滤器，退出后自动恢复原过滤器。pattern 语法沿用 JEP 290：maxbytes、类名/java.* 通配、!* 取反、maxdepth 等。

import java.io.InvalidClassException;
import java.io.ObjectInputFilter;
import java.io.ObjectInputStream;
import java.io.ObjectOutputStream;
import java.nio.file.Files;
public class Filter17 {
  public static void main(String[] a) throws Exception {
    var filter = ObjectInputFilter.Config.createFilter("maxbytes=1000;java.lang.*;!*");
    var p = Files.createTempFile("filter", ".bin");
    try (var oos = new ObjectOutputStream(Files.newOutputStream(p))) {
      oos.writeObject(1);
      oos.writeObject(new int[300]);
      oos.writeObject(7);
    }
    try (var ois = new ObjectInputStream(Files.newInputStream(p))) {
      ois.setObjectInputFilter(filter);
      System.out.println("read1=" + ois.readObject());
      var arr = (int[]) ois.readObject();
      System.out.println("read2.len=" + arr.length);
      try {
        ois.readObject();
        System.out.println("unexpectedly accepted");
      } catch (InvalidClassException e) {
        System.out.println("rejected: " + e.getMessage());
      }
    }
    Files.deleteIfExists(p);
  }
}
// 运行输出：
// read1=1
// read2.len=300
// rejected: filter status: REJECTED

✅ 实测通过（JDK 25）。三个实测细节：① maxbytes 数的是已读流字节（读到第 1310 字节越过 1000，第三个对象直接 REJECTED）；② pattern 必须放行超类——漏写 java.lang.* 时，读第一个 Integer 就会因超类 java.lang.Number 命中 !* 被拒（实测日志 cls=java.lang.Number bytes=75 -> REJECTED）；③ String 走 TC_STRING 快捷路径，根本不触发过滤器（readString() 不调 filterCheck），所以示例改用 Integer/int[]。

17.6 HexFormat

字节↔十六进制互转、带分隔符与大小写定制、单字符两位输出——把过去手写的 String.format("%02x") 循环收成 API（@since 17）。

import java.util.HexFormat;
public class Hex17 {
  public static void main(String[] a) {
    var hf = HexFormat.of();
    System.out.println(hf.formatHex(new byte[]{1, 15, (byte) 255}));
    System.out.println(hf.parseHex("010ff0").length);
    System.out.println(HexFormat.ofDelimiter(":").withUpperCase().formatHex(new byte[]{10, 20}));
    System.out.println(hf.toHexDigits('A'));
  }
}
// 运行输出：
// 010fff
// 3
// 0A:14
// 0041

✅ 实测通过（JDK 25）。要点：parseHex 宽容空白与大小写；toHexDigits(char) 给码点两位十六进制。

17.7 Sealed 的反射能力（@since 17）

框架（序列化、校验、代码生成）从此能问出一个类型是否受控、受控到哪些子类。

public class SealedRef17 {
  public sealed interface Node permits Leaf, Branch {}
  public record Leaf(int v) implements Node {}
  public record Branch(Node l, Node r) implements Node {}
  public static void main(String[] a) {
    System.out.println(Node.class.isSealed());
    var subs = Node.class.getPermittedSubclasses();
    System.out.println(subs.length + " " + subs[0].getSimpleName() + "," + subs[1].getSimpleName());
    System.out.println(String.class.isSealed() + " permitted=" + java.util.Arrays.toString(String.class.getPermittedSubclasses()));
  }
}
// 运行输出：
// true
// 2 Leaf,Branch
// false permitted=null

✅ 实测通过（JDK 25）。要点：isSealed() 返回 false 时 getPermittedSubclasses() 返回 null（不是空数组）——JLS 对 permits 的描述是「未 sealed 则为「null」」，调用方必须判空；String 未受控，故 false permitted=null。

18.1 Pattern Matching for switch 第二次预览（JEP 420）

相对 406 的两处实质改动：① dominance 检查——常量标签必须排在同类型守卫标签之前（case -1, 1 → case Integer i && i > 0 → case Integer i）；② 穷尽性推导更精确——当 sealed 泛型层次里，某个许可子类只实例化了泛型超类的某一侧时，该 case 可省略。420 的正文已预留「record/array patterns 待 JEP 405 加入」，即 18 时点 switch 还不能解构 record。

public class PMSW18 {
  sealed interface Shape permits Circle, Square, Other {}
  record Circle(double r) implements Shape {}
  record Square(double s) implements Shape {}
  record Other(String tag) implements Shape {}
  static String name(Shape sh) {
    return switch (sh) {
      case Circle c -> "circle " + c.r();
      case Square s -> "square " + s.s();
      case Other o -> "other:" + o.tag();
    };
  }
  static String kind(Object o) {
    return switch (o) {
      case null -> "null";
      case Integer i when i > 0 -> "pos";
      case Integer i -> "non-pos";
      case String s -> "str:" + s;
      default -> "other";
    };
  }
  public static void main(String[] a) {
    System.out.println(name(new Circle(1.5)) + "/" + name(new Square(2)) + "/" + name(new Other("x")));
    System.out.println(kind(null) + "/" + kind(5) + "/" + kind(-1) + "/" + kind("s") + "/" + kind(1.5));
  }
}
// 运行输出：
// circle 1.5/square 2.0/other:x
// null/pos/non-pos/str:s/other

✅ 实测通过（JDK 25）。要点：Shape 受控 → name() 三个 case 已覆盖全部许可子类，无需 default（穷尽性由编译器验证）；kind() 走的是「非受控类型」，必须有 default 兜住 Double；带守卫的 pos 必须写在 non-pos 前（dominance）。

18.3 UTF-8 成为默认字符集（JEP 400）

18 起 Charset.defaultCharset()、new String(byte[])、无参流读写默认 UTF-8，与 file.encoding/OS locale 解绑——消除「同一份代码在中文 Windows 上是 GBK、在 Linux 上是 UTF-8」的坑。原 locale 相关值改由 native.encoding 提供。

import java.nio.charset.Charset;
public class Utf818 {
  public static void main(String[] a) {
    var utf8 = new byte[]{(byte) 0xC3, (byte) 0xA9};
    System.out.println(new String(utf8));
    System.out.println(System.getProperty("file.encoding"));
    System.out.println(Charset.defaultCharset());
    System.out.println(new String(utf8, Charset.forName("ISO-8859-1")));
  }
}
// 运行输出：
// é
// UTF-8
// UTF-8
// Ã©

✅ 实测通过（JDK 25）。要点：同一串字节 C3 A9，UTF-8 解出 é、Latin-1 解出 Ã©——「乱码」就是解码端选错 charset；JDK 25 的 file.encoding/默认 charset 恒为 UTF-8（18 的 JEP 400 之后不可再配回平台默认）。

18.4 jwebserver（JEP 408）

bin/jwebserver 是 com.sun.net.httpserver.HttpServer 的极简封装：起一个静态目录服务器（只读 GET/HEAD、单线程队列、访问日志、GET / 列目录），定位是「python -m http.server 那种开发用小工具」，不支持 CGI/HTTPS。

import com.sun.net.httpserver.HttpServer;
import java.net.InetSocketAddress;
import java.net.URL;
import java.nio.charset.StandardCharsets;
public class Web18 {
  public static void main(String[] a) throws Exception {
    var server = HttpServer.create(new InetSocketAddress("127.0.0.1", 0), 0);
    server.createContext("/", ex -> {
      var body = "hello from simple server".getBytes(StandardCharsets.UTF_8);
      ex.sendResponseHeaders(200, body.length);
      ex.getResponseBody().write(body);
      ex.close();
    });
    server.start();
    int port = server.getAddress().getPort();
    try (var in = new URL("http://127.0.0.1:" + port + "/").openStream()) {
      System.out.println(new String(in.readAllBytes(), StandardCharsets.UTF_8));
    }
    server.stop(0);
    System.out.println("stopped");
  }
}
// 运行输出：
// hello from simple server
// stopped

✅ 实测通过（JDK 25）。jwebserver 本身是 CLI：手工实测 bin/jwebserver --help 正常输出中文用法（含 --port/--dir/--timeout），启动后需 Ctrl+C 退出，故不带 data-run；示例改用底层 HttpServer 并 stop(0) 立即结束。

18.6 互联网地址解析 SPI（JEP 418）

把「主机名 → IP」从 InetAddress 内部硬编码里拆出来，允许插拔解析实现（走自定义 DNS、服务发现、测试桩等），默认实现仍是系统解析器。

import java.net.InetAddress;
import java.net.spi.InetAddressResolver;
import java.net.spi.InetAddressResolverProvider;
import java.util.ServiceLoader;
public class Resolver18 {
  public static void main(String[] a) throws Exception {
    long n = ServiceLoader.load(InetAddressResolverProvider.class).stream().count();
    System.out.println("registered-providers=" + n);
    System.out.println(InetAddress.getLoopbackAddress().getHostAddress());
    System.out.println(InetAddressResolver.class.getName());
  }
}
// 运行输出：
// registered-providers=0
// 127.0.0.1
// java.net.spi.InetAddressResolver

✅ 实测通过（JDK 25）。要点：ServiceLoader 计数为 0（没有 provider 注册文件时走 JDK 默认解析）；java.net.spi.InetAddressResolver / InetAddressResolverProvider 是 18 起 java.base 的类型（已用 javap 核对存在）。

// ❌ 未实测：完整 SPI 实现需要 META-INF/services 注册文件与真实 DNS 场景，
// 超出「单文件 data-run」验证范围；接口形态已核对（18 起，JEP 418）
import java.net.InetAddress;
import java.net.UnknownHostException;
import java.net.spi.InetAddressResolver;
import java.net.spi.InetAddressResolverProvider;
import java.util.stream.Stream;

class MyResolver implements InetAddressResolver {
  @Override
  public Stream<InetAddress> lookupByName(String host, LookupPolicy policy) throws UnknownHostException {
    if (host.equals("demo.local")) return Stream.of(InetAddress.getByAddress(new byte[]{127, 0, 0, 1}));
    throw new UnknownHostException(host);
  }
  @Override
  public String lookupByAddress(byte[] addr) throws UnknownHostException {
    throw new UnknownHostException(java.util.Arrays.toString(addr));
  }
}
class MyResolverProvider extends InetAddressResolverProvider {
  @Override public InetAddressResolver get(Configuration cfg) { return new MyResolver(); }
  @Override public String name() { return "demo resolver"; }
}
// 注册文件 META-INF/services/java.net.spi.InetAddressResolverProvider 内容一行：
//   MyResolverProvider
// 之后 InetAddress.getAllByName("demo.local") 会经 ServiceLoader 走到上面的 lookupByName

18.7 @Override 用在接口方法实现上（⚠️ 素材勘误）

勘误：这不是 JDK 18 的语言变更

素材把「@Override 可标注实现接口方法的重写」列在 18。核对：JLS SE 16 / 17 / 18 / 19 §9.6.4.4 正文逐字一致（都写 "method declaration that overrides or implements…"），且 JLS 明说该行为「与 Java SE 5.0 不同」——Java SE 6 起就合法（Java SE 5 才会报错）。JDK 16/17/18 的 Override javadoc 也都是 "does override or implement a method declared in a supertype"。JDK 18 与之相关的只有 JDK-8275360（在 javax.annotation.processing 里补用 @Override），属代码风格整改。故 18.7 的状态是「非语言变更」，不是 18 新增。

示例照给（25 实测通过）：接口方法与接口 default 方法的实现都可标 @Override。

public class Override18 {
  interface Greeter {
    String greet(String name);
    default String hi() { return "hi"; }
  }
  static class Impl implements Greeter {
    @Override public String greet(String name) { return "hello " + name; }
    @Override public String hi() { return "hey"; }
  }
  public static void main(String[] a) {
    Greeter g = new Impl();
    System.out.println(g.greet("ann") + " " + g.hi());
  }
}
// 运行输出：
// hello ann hey

✅ 实测通过（JDK 25）。要点：@Override 的价值是让「拼错方法名/签名」直接编译失败；default 方法的实现同样适用。

19.1 Record Patterns（JEP 405 · 预览）

把 record 组件直接解构成模式变量：能用在 instanceof 之后，也能当 switch 的 case 标签；支持嵌套解构与 var。19 预览 → 21（JEP 440）转正，所以 25 上免预览开关。

public class RecPat19 {
  record Point(int x, int y) {}
  record Rect(Point ul, Point lr) {}
  static String describe(Object o) {
    if (o instanceof Point(int x, int y)) return "point " + (x + y);
    if (o instanceof Rect(Point(var x1, var y1), Point(var x2, var y2))) return "rect " + (x2 - x1) + "x" + (y2 - y1);
    return "other";
  }
  public static void main(String[] a) {
    System.out.println(describe(new Point(1, 2)));
    System.out.println(describe(new Rect(new Point(0, 0), new Point(4, 3))));
    System.out.println(describe(9));
  }
}
// 运行输出：
// point 3
// rect 4x3
// other

✅ 实测通过（JDK 25）。要点：解构失败即「模式不匹配」落到下一分支（不是 ClassCastException）——这正是模式与强转的区别；嵌套 Rect(Point(...), Point(...)) 逐层拆；组件可用 var（类型由 record 组件推断）。

19.2 Pattern Matching for switch 第三次预览（JEP 427 · when 守卫）

守卫语法从 17/18 的 p && e 改为 case P when e（引入 when 上下文关键字），与 record patterns 结合后 switch 才完整；427 → 20（433）→ 21（441）转正。

public class SwitchPM19 {
  record Point(int x, int y) {}
  static String classify(Object o) {
    return switch (o) {
      case Point(int x, int y) when x == y -> "diagonal " + x;
      case Point(int x, int y) -> "point " + x + "," + y;
      case String s when s.isEmpty() -> "empty";
      case String s -> "str:" + s;
      case Integer i when i % 2 == 0 -> "even " + i;
      case Integer i -> "odd " + i;
      case null -> "null";
      default -> "other";
    };
  }
  public static void main(String[] a) {
    System.out.println(classify(new Point(3, 3)) + "/" + classify(new Point(1, 2)));
    System.out.println(classify("") + "/" + classify("ab") + "/" + classify(4) + "/" + classify(5));
    System.out.println(classify(null) + "/" + classify(1.5));
  }
}
// 运行输出：
// diagonal 3/point 1,2
// empty/str:ab/even 4/odd 5
// null/other

✅ 实测通过（JDK 25）。要点：Point(int x, int y) 是 record pattern，配 when x == y 组成守卫标签；Point 解构 + 守卫 + 无守卫两段必须按序排列（同类型 dominance）；19 当年需 --enable-preview --release 19，25 免开关。

19.3 Foreign Function & Memory API（JEP 424 · 预览）

「JSR 393 梦想成真」：用 Arena + MemorySegment 安全地做堆外内存分配/读写（生命周期作用域化、没有手工 free），再用 Linker 调用原生函数——替代 JNA/JNI。三条史实链容易记混，先勘误：

勘误：19/20 的 FFM 在 java.lang.foreign（预览），不是 jdk.incubator.foreign（孵化）

jdk.incubator.foreign 是 14–18 的孵化包（JEP 375/383/393/389/412/419，17/18 分别是 JEP 412/419）；JDK 19 起移到 java.base 的 java.lang.foreign，状态是「预览」（JEP 424，19；JEP 434，20；JEP 442，21 第三次预览），22 才转正（JEP 454）。→ 素材把「jdk.incubator.foreign」记到 19/20 属于版本错位。

版本忠实写法（史料，JDK 25 上都跑不了）：

// ❌ 未实测：FFM 三条史实链，JDK 25 上均不可编译
// ① 14–18：孵化包 jdk.incubator.foreign，需 --add-modules jdk.incubator.foreign
//    （17 = JEP 412，18 = JEP 419 第二次孵化）——25 上该包已不存在
// ② 19/20：改到 java.base 的 java.lang.foreign，状态是「预览」
//    （19 = JEP 424，20 = JEP 434），需 javac --enable-preview --release 19
//    ——25 的 javac 不再接受 --release 19，无法复现当年预览形态
// ③ 22：JEP 454 转正，免预览 → 见下方 19.3 的 ✅ 现行示例

JDK 25 现行形态（=22 转正 API，免预览；本页按「同一特性的现代等价」计 ✅）：

import java.lang.foreign.Arena;
import java.lang.foreign.MemorySegment;
import java.lang.foreign.ValueLayout;
public class Ffm19 {
  public static void main(String[] a) {
    MemorySegment freed;
    try (var arena = Arena.ofConfined()) {
      MemorySegment seg = arena.allocate(16);
      seg.set(ValueLayout.JAVA_INT, 0, 42);
      seg.set(ValueLayout.JAVA_INT, 4, 58);
      System.out.println(seg.get(ValueLayout.JAVA_INT, 0) + " " + seg.get(ValueLayout.JAVA_INT, 4));
      System.out.println("byteSize=" + seg.byteSize());
      freed = seg;
    }
    System.out.println("scope-alive=" + freed.scope().isAlive());
  }
}
// 运行输出：
// 42 58
// byteSize=16
// scope-alive=false

✅ 实测通过（JDK 25）。要点：Arena.ofConfined() 的作用域关闭后段即失效（scope().isAlive() 变 false）——这是 FFM 相对 JNI 的核心安全属性（生命周期绑定、越界访问抛异常而不是踩别人内存）；ValueLayout.JAVA_INT 读写是显式字节序，跨平台可预测。
