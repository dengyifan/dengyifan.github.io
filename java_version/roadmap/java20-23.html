20.1 Record Patterns（JEP 432 · 第二次预览）

把 record 的组件直接解构成模式变量：既能用在 instanceof 后，也能当 switch 的 case 标签，支持嵌套解构与 var。19 首次预览（JEP 405），20 第二次预览，21（JEP 440）转正——所以 25 上免预览开关。

import java.util.List;
public class RP20 {
  record Point(int x, int y) {}
  record Box(Point p, String tag) {}
  static String describe(Object o) {
    if (o instanceof Point(var x, var y)) return "P(" + x + "," + y + ")";
    if (o instanceof Box(Point(var x, var y), var tag)) return "B(" + x + "," + y + "," + tag + ")";
    return "?";
  }
  public static void main(String[] a) {
    var box = new Box(new Point(3, 4), "crate");
    System.out.println(describe(new Point(1, 2)));
    System.out.println(describe(box));
    System.out.println(describe(List.of(1)));
    String s = switch (box) {
      case Box(Point(var x, var y), var t) when x == y -> "square " + t;
      default -> "other";
    };
    System.out.println(s);
  }
}
// 运行输出：
// P(1,2)
// B(3,4,crate)
// ?
// other

✅ 实测通过（JDK 25）。要点：组件可以用 var（类型由组件推断），可以只解构需要的组件；解构不匹配（如把 List 交给 Box(...)）就落到下一个分支，这正是「模式」与强转的区别。

20.2 Pattern Matching for switch 第四次预览（JEP 433）

17 首次预览（JEP 406）→ 18（420）→ 19（427）→ 20 第四次（433）→ 21 转正（JEP 441）。这一版把类型模式、守卫 when、null 显式标签、穷尽性检查四件事定型。

public class PMSW20 {
  static String label(Object o) {
    return switch (o) {
      case null -> "null";
      case String s when s.length() > 3 -> "long:" + s;
      case String s -> "str:" + s;
      case Integer i when i % 2 == 0 -> "even:" + i;
      case Integer i -> "odd:" + i;
      default -> "other";
    };
  }
  public static void main(String[] a) {
    System.out.println(label(null));
    System.out.println(label("hello"));
    System.out.println(label("hi"));
    System.out.println(label(4));
    System.out.println(label(7));
    System.out.println(label(3.14));
  }
}
// 运行输出：
// null
// long:hello
// str:hi
// even:4
// odd:7
// other

✅ 实测通过（JDK 25）。要点：case null 必须显式写，否则 null 会直接 NPE；守卫 when 只做筛选，不绑定变量；同类型标签按书写顺序匹配，先写带守卫的。

20.3 Scoped Values（JEP 429 · 孵化）

用「不可变 + 作用域绑定」替代 ThreadLocal：写一次、只在 where(...).run(...) 的动态范围内可读、出了作用域自动失效——专为海量虚拟线程设计（不随线程泄漏、无 set 乱改）。

// ❌ 未实测：JDK 20 孵化写法（JEP 429 · 孵化模块 jdk.incubator.concurrent）
// 需 javac/java --add-modules jdk.incubator.concurrent；该孵化模块已从 JDK 25 移除
import jdk.incubator.concurrent.ScopedValue;

final static ScopedValue<String> WHO = ScopedValue.newInstance();

ScopedValue.where(WHO, "main-thread").run(() -> {
    System.out.println(WHO.get());   // 只在 run(...) 的作用域内可读
});
// 形态取自 JEP 429 正文（newInstance / where / run / get），与 25 正式 API 同形

25 的等价正式写法（JEP 446 在 21 转为预览 → JEP 506 在 25 转正，java.lang.ScopedValue）：

public class SV20 {
  static final ScopedValue<String> WHO = ScopedValue.newInstance();
  public static void main(String[] a) {
    ScopedValue.where(WHO, "main-thread").run(() -> {
      System.out.println("inside=" + WHO.get());
      try {
        Thread t = new Thread(() -> System.out.println("child=" + (WHO.isBound() ? WHO.get() : "unbound")));
        t.start();
        t.join();
      } catch (InterruptedException e) {
        Thread.currentThread().interrupt();
      }
    });
    System.out.println("after=" + WHO.isBound());
  }
}
// 运行输出：
// inside=main-thread
// child=unbound
// after=false

✅ 实测通过（JDK 25，免预览）。注意输出里的 child=unbound：裸 new Thread() 不继承绑定，绑定只在当前线程的动态作用域里（要跨线程传递得配合结构化并发的子任务——见 结构化并发 与 线程局部变量 两课）。作用域一结束 isBound() 立刻变回 false。

20.4 Foreign Function & Memory API 第二次预览（JEP 434）

// ❌ 未实测：JDK 20 是预览 API（JEP 434，第二次预览），关键形态：
//   try (var session = MemorySession.open()) {            // 会话作用域
//       var seg = MemorySegment.allocate(16, session);    // 在会话内分配原生/堆内存
//       seg.set(ValueLayout.JAVA_INT, 0, 42);
//   }
// 演进：17 孵化(JEP 412) → 18 孵化(419) → 19 预览(424) → 20 预览(434)
//       → 21 预览(442，MemorySession 被 Arena 取代) → 22 转正(454)
// JDK 25 已无 MemorySession，可运行的等价写法见下（14.7 的 Arena 版 mmap 同族）。
import java.lang.foreign.Arena;
import java.lang.foreign.MemorySegment;
import java.lang.foreign.ValueLayout;
public class FFM20 {
  public static void main(String[] a) {
    try (var arena = Arena.ofConfined()) {
      MemorySegment seg = arena.allocate(16);
      seg.set(ValueLayout.JAVA_INT, 0, 42);
      seg.set(ValueLayout.JAVA_INT, 4, 58);
      System.out.println(seg.get(ValueLayout.JAVA_INT, 0) + "/" + seg.get(ValueLayout.JAVA_INT, 4));
      System.out.println(seg.get(ValueLayout.JAVA_BYTE, 0) == 42);
    }
  }
}
// 运行输出：
// 42/58
// true

✅ 实测通过（JDK 25；FFM 自 22/JEP 454 转正进 java.base，免预览）。Arena.ofConfined() 是「单线程作用域」：try 结束即释放整块内存——这就是它替代 free() 的方式。

21.1 Record Patterns 转正（JEP 440）

20 的预览在 21 定稿：嵌套 record、var、组件类型推断全部保留，语法不再变化。

public class RP21 {
  record Point(int x, int y) {}
  record Segment(Point from, Point to) {}
  static String show(Object o) {
    return switch (o) {
      case Segment(Point(var x1, var y1), Point(var x2, var y2))
          when x1 == x2 -> "vertical x=" + x1;
      case Segment(Point(var x1, var y1), Point(var x2, var y2))
          when y1 == y2 -> "horizontal y=" + y1;
      case Point(var x, var y) -> "point " + x + "," + y;
      case null -> "nothing";
      default -> "unknown";
    };
  }
  public static void main(String[] a) {
    System.out.println(show(new Segment(new Point(2, 1), new Point(2, 9))));
    System.out.println(show(new Segment(new Point(1, 5), new Point(7, 5))));
    System.out.println(show(new Point(4, 4)));
    System.out.println(show(null));
  }
}
// 运行输出：
// vertical x=2
// horizontal y=5
// point 4,4
// nothing

✅ 实测通过（JDK 25）。深度嵌套（Segment(Point(...), Point(...))）一次解构到底；两个 when 守卫的分支不命中时，会继续往下试 case Point(...)。

21.2 Pattern Matching for switch 转正（JEP 441）

与 Record Patterns 同批转正。三条硬规则：null 必须显式建模；带守卫的分支写在裸类型分支之前；对 sealed 类型可以省略 default（编译器做穷尽性检查）。

public class SW21 {
  sealed interface Shape permits Circle, Rect {}
  record Circle(double r) implements Shape {}
  record Rect(double w, double h) implements Shape {}
  static String describe(Object o) {
    return switch (o) {
      case Shape s when s instanceof Circle c && c.r() > 10 -> "big circle " + c.r();
      case Circle c -> "circle " + c.r();
      case Rect r when r.w() == r.h() -> "square " + r.w();
      case Rect r -> "rect " + r.w() + "x" + r.h();
      case Integer i when i > 0 -> "count " + i;
      case null -> "empty";
      default -> "other";
    };
  }
  public static void main(String[] a) {
    System.out.println(describe(new Circle(12.0)));
    System.out.println(describe(new Circle(3.0)));
    System.out.println(describe(new Rect(4, 4)));
    System.out.println(describe(new Rect(4, 5)));
    System.out.println(describe(7));
    System.out.println(describe(null));
    System.out.println(describe("x"));
  }
}
// 运行输出：
// big circle 12.0
// circle 3.0
// square 4.0
// rect 4.0x5.0
// count 7
// empty
// other

✅ 实测通过（JDK 25）。注意第一行：case Shape s when s instanceof Circle c && ... 这种「守卫里再做模式匹配」是 21 之后才顺畅的写法——守卫内的模式变量只在守卫为真时可见。

21.3 String Templates（JEP 430 · 预览 → 23 撤回）

当年的卖点：把 STR."... \{expr}" 这种「模板字面量」交给处理器做插值/校验，替代手写 + 拼接与 String.format。它先在 21 预览（JEP 430）、22 二次预览（JEP 459），23 的第三次预览 JEP 465 被列为 Withdrawn，此后彻底移除。

// ❌ 未实测：JDK 21/22 预览写法（JEP 430 / JEP 459）
// JDK 25 已撤回该特性：STR 模板处理器不存在，这段代码在 25 上 javac 直接报
// 「错误: 非法转义符」（指向 \{），因此无法在本机实测。
public class StrTpl21 {
  public static void main(String[] a) {
    String name = "world";
    int x = 40;
    String s1 = STR."Hello \{name}!";      // 字符串插值
    String s2 = STR."x = \{x}";
    System.out.println(s1 + " / " + s2);
  }
}
// 若在 JDK 21/22 开启 --enable-preview 编译运行，预期输出（未实测）：
// Hello world! / x = 40
// 现代等价写法（25 可跑）：System.out.println("Hello " + name + "! / x = " + x);

❌ 未实测（特性已撤回）。本机实测：javac 对 STR."... \{x}" 报「非法转义符」，可佐证 25 语法层已不认识模板字面量。

21.4 Unnamed Patterns and Variables（JEP 443 · 预览）

给「我只需要它存在、不需要它的值」的位置一个统一的下划线：var _、资源变量、增强 for 的循环变量、解构后不用的组件、lambda 形参。21 预览，22（JEP 456）转正。

import java.nio.file.Files;
import java.nio.file.Path;
import java.util.List;
public class UNM21 {
  record Box(String tag) {}
  public static void main(String[] a) throws Exception {
    var _ = new Object();                       // 未命名变量：只为触发资源/顺序语义
    int used = 0;
    for (String _ : List.of("a", "b", "c")) used++;
    System.out.println("loop=" + used);

    Path p = Files.createTempFile("unm", ".txt");
    try (var _ = Files.newBufferedReader(p)) {  // 未命名资源变量：关了就行，不引用
      System.out.println("opened");
    }
    Files.deleteIfExists(p);

    Object o = new Box("crate");
    String s = switch (o) {
      case Box(String _) -> "named box";        // 未命名模式：解构但不使用
      default -> "other";
    };
    System.out.println(s);
  }
}
// 运行输出：
// loop=3
// opened
// named box

✅ 实测通过（JDK 25，22 起免预览）。与匿名占位名（ignored、tmp）的区别：_ 是语言关键字，编译器知道你故意不用，能顺带消除「未使用变量」告警。

21.5 Unnamed Classes and Instance Main Methods（JEP 445 · 预览）

单文件小程序不必再写 public class X + static void main：顶层写 void main() 即可，编译器生成未命名类。后续几次预览里它一路改名：22/23「Implicitly Declared Classes」→ 24「Simple Source Files」（JEP 495）→ 25「Compact Source Files and Instance Main Methods」（JEP 512，正式）。

void main(String... args) {
  String who = "Java 21";
  System.out.println("unnamed class in " + who);
  System.out.println("args=" + args.length);
}
// 运行输出：
// unnamed class in Java 21
// args=0

✅ 实测通过（JDK 25；21 当年需 --enable-preview --release 21，25 已是正式特性）。main 是实例方法，所以可以自然地调用同文件里的其它方法与字段；args 由启动器注入。

21.6 Sequenced Collections（JEP 431）

给所有「有顺序的集合」统一一套端点操作：新接口 SequencedCollection（List/Deque 继承）、SequencedSet、SequencedMap，并补齐 getFirst/getLast/addFirst/addLast/removeFirst/removeLast/reversed。

import java.util.ArrayDeque;
import java.util.List;
import java.util.SequencedCollection;
public class SEQ21 {
  public static void main(String[] a) {
    List<String> list = List.of("a", "b", "c");
    System.out.println(list.getFirst() + " " + list.getLast());
    System.out.println(list.reversed());
    System.out.println(list.reversed().getFirst());

    ArrayDeque<String> dq = new ArrayDeque<>(List.of("x", "y"));
    dq.addFirst("z");
    dq.addLast("w");
    System.out.println(dq);
    System.out.println(dq.removeFirst() + "/" + dq.removeLast());

    SequencedCollection<String> sc = new ArrayDeque<>(List.of("p", "q"));
    System.out.println(sc.getFirst() + " " + sc.getLast());
  }
}
// 运行输出：
// a c
// [c, b, a]
// c
// [z, x, y, w]
// z/w
// p q

✅ 实测通过（JDK 25）。实测确认：List.of(...) 虽然不可变，但 getFirst/getLast/reversed 属于接口默认方法，照样可用；reversed() 返回的是视图（改视图等于改原集合，对不可变集合只是读）。

21.7 Scoped Values（JEP 446 · 预览）

从 20 的孵化模块搬进 java.lang 变成预览 API。25 形态：where(...).run(...) 执行不求值、where(...).call(...) 执行并返回结果，读取用 get()，判断用 isBound()。

public class SV21 {
  static final ScopedValue<String> USER = ScopedValue.newInstance();
  static String read() {
    return USER.isBound() ? USER.get() : "unbound";
  }
  public static void main(String[] a) throws Exception {
    String v = ScopedValue.where(USER, "alice").call(SV21::read);
    System.out.println("call=" + v);
    ScopedValue.where(USER, "bob").run(() -> System.out.println("run=" + read()));
    System.out.println("after=" + read());
  }
}
// 运行输出：
// call=alice
// run=bob
// after=unbound

✅ 实测通过（JDK 25，免预览——JEP 506 已在 25 转正）。call 的返回值直接拿到、嵌套绑定只在内层可见，是它比 ThreadLocal 好用的两个关键点。

21.8 Key Encapsulation Mechanism API（JEP 452）

把「后量子密钥封装」（ML-KEM）纳入标准 API：javax.crypto.KEM 统一了封装端/解封装端的三步流程，底层算法由 provider 提供。

import java.security.KeyPair;
import java.security.KeyPairGenerator;
import java.util.Arrays;
import javax.crypto.KEM;
import javax.crypto.SecretKey;
public class KEM21 {
  public static void main(String[] a) throws Exception {
    KEM kem = KEM.getInstance("ML-KEM");
    KeyPairGenerator kpg = KeyPairGenerator.getInstance("ML-KEM");
    KeyPair kp = kpg.generateKeyPair();

    KEM.Encapsulated enc = kem.newEncapsulator(kp.getPublic()).encapsulate();
    SecretKey senderKey = enc.key();
    byte[] ct = enc.encapsulation();

    SecretKey receiverKey = kem.newDecapsulator(kp.getPrivate()).decapsulate(ct);
    boolean same = Arrays.equals(senderKey.getEncoded(), receiverKey.getEncoded());
    System.out.println("kem=" + kem.getAlgorithm());
    System.out.println("ctLen=" + ct.length + " keyLen=" + senderKey.getEncoded().length);
    System.out.println("sharedEqual=" + same);
  }
}
// 运行输出：
// kem=ML-KEM
// ctLen=1088 keyLen=32
// sharedEqual=true

✅ 实测通过（JDK 25）。要点与坑：生成端调用的是 encapsulate()（不是 generateEncapsulation()）；返回对象是 KEM.Encapsulated，取密钥用 .key()、取密文用 .encapsulation()（不是 secretKey()）；两边算出的 getEncoded() 逐字节相等即共享密钥成立。实测 getInstance("X25519")/"DH"/"RSA" 在本机 JDK 25 上取不到（算法名以 provider 列表为准，本机可用的是 ML-KEM）。

21.9 StringBuilder / StringBuffer 的 repeat 增强

素材勘误：21 给 StringBuilder 新增的不是 indexOf / lastIndexOf /charAt

素材称 Java 21 为 StringBuilder/StringBuffer 增加了 indexOf/lastIndexOf/charAt——这三个方法在 JDK 25 源码里没有任何 @since 标注（即随类原生存在，远早于 17，更不是 21），String.indexOf 更是 JDK 1.0 就有。21 真正新增的是两个重载：repeat(int codePoint, int count) 与 repeat(CharSequence str, int count)（java.base/java/lang/StringBuilder.java 中明确标注 @since 21）。另外 String.repeat(int) 是 JDK 11 就有的，别混。

public class SB21 {
  public static void main(String[] a) {
    StringBuilder sb1 = new StringBuilder("ab");
    sb1.repeat("*", 3);                       // 追加 "*" 3 次
    System.out.println(sb1);

    StringBuilder sb2 = new StringBuilder();
    sb2.repeat("ab", 2);                      // 追加 "ab" 2 次
    System.out.println(sb2);

    StringBuilder sb3 = new StringBuilder("x");
    sb3.repeat('!', 4);                       // 追加码点 '!' 4 次
    sb3.append(" | ").append("cd".repeat(2)); // String.repeat(int) 是 JDK 11 就有的
    System.out.println(sb3);

    System.out.println(sb1.indexOf("*") + "/" + sb1.charAt(0));
  }
}
// 运行输出：
// ab***
// abab
// x!!!! | cdcd
// 2/a

✅ 实测通过（JDK 25）。语义实测确认：sb.repeat(分隔, 次数) 是把参数追加到当前内容之后（返回 this，就地修改），所以 "ab".repeat("*", 3) 是 ab*** 而不是 ***ab；两个参数的顺序是 (要重复的东西, 次数)，写成 repeat(3, "*") 编译不过。最后一行的 indexOf/charAt 顺带验证它们与 21 无关（一直都在）。

22.1 Unnamed Variables & Patterns 转正（JEP 456）

import java.nio.file.Files;
import java.nio.file.Path;
import java.util.List;
import java.util.function.Function;
public class UNM22 {
  record Box(String tag) {}
  public static void main(String[] a) throws Exception {
    var _ = new Object();
    int n = 0;
    for (String _ : List.of("x", "y")) n++;

    Path p = Files.createTempFile("unm22", ".txt");

    Files.deleteIfExists(p);

    Object o = new Box("b");

      default -> "other";

}

✅ 实测通过（JDK 25，正式特性免开关）。注意 _ 一旦用作变量名就是「未命名」，不能再当标识符使用。

22.3 Implicitly Declared Classes & Instance main（JEP 463 · 第二次预览）

22.4 Statements before super(...)（JEP 447 · 预览）

打破「构造器第一条必须是 super(...)/this(...)」：允许在显式构造调用之前放语句（prologue），但不得触碰正在构造的实例（不能读字段、调方法），于是可以先校验、先算参数、先打日志。

class Base22 {
  Base22(int v) { System.out.println("base " + v); }
}
class Child22 extends Base22 {
  Child22(int v) {
    if (v <= 0) throw new IllegalArgumentException("bad " + v);
    int doubled = v * 2;
    System.out.println("stmts " + doubled);
    super(doubled);
    System.out.println("after");
  }
}
public class SBS22 {
  public static void main(String[] a) {
    new Child22(5);
    try {
      new Child22(0);
    } catch (IllegalArgumentException e) {
      System.out.println("caught " + e.getMessage());
    }
  }
}
// 运行输出：
// stmts 10
// base 10
// after
// caught bad 0

✅ 实测通过（JDK 25，免预览——JEP 513「Flexible Constructor Bodies」已在 25 转正；22 当年需 --enable-preview --release 22）。输出顺序即「prologue → super → epilogue」；失败路径在校验处就抛出，父类构造器根本没跑。

22.5 Stream Gatherers（JEP 461 · 预览）

给 Stream 补上「多对多/有状态」的中间操作：自定义 Gatherer，或直接用内置的 windowFixed、windowSliding、fold。24（JEP 485）转正。

import java.util.stream.Gatherers;
import java.util.stream.Stream;
public class GAT22 {
  public static void main(String[] a) {
    var windows = Stream.of(1, 2, 3, 4, 5).gather(Gatherers.windowFixed(2)).toList();
    System.out.println(windows);
    var running = Stream.of(1, 2, 3, 4).gather(Gatherers.fold(() -> 0, Integer::sum)).toList();
    System.out.println(running);
    System.out.println(Stream.of("a", "b", "c").gather(Gatherers.windowFixed(3)).count());
  }
}
// 运行输出：
// [[1, 2], [3, 4], [5]]
// [10]
// 1

✅ 实测通过（JDK 25，免预览）。要点：windowFixed 末尾不足一窗的元素照样成窗（[5]）；fold 实测只吐一个终值（JDK 25 源码 finisher 处才 downstream.push(state.value)），别把它当「滚动累计流」用。

22.6 Class-File API（JEP 457 · 预览）

用对象模型读 class 文件（ClassFile.of().parse(...)），替代散落多年的 com.sun.tools.classfile 与 ASM。24（JEP 484）转正。

import java.lang.classfile.ClassFile;
import java.lang.classfile.ClassModel;
public class CF22 {
  static int helper(int x) { return x * 2; }
  public static void main(String[] a) throws Exception {
    byte[] bytes;
    try (var in = CF22.class.getResourceAsStream("CF22.class")) {
      bytes = in.readAllBytes();
    }
    ClassModel model = ClassFile.of().parse(bytes);
    model.methods().forEach(m -> System.out.println(m.methodName().stringValue()));
    System.out.println("methods=" + model.methods().size() + " bytes=" + bytes.length);
  }
}
// 运行输出：
// <init>
// helper
// main
// lambda$main$0
// methods=4 bytes=2466

✅ 实测通过（JDK 25）。要点：parse 得到 ClassModel（惰性、只读的结构化视图），methodName() 返回 Utf8Entry，取字符串用 stringValue()；连编译器生成的 lambda$main$0 和默认构造器 <init> 都看得见。

22.7 FFM 转正（JEP 454）

预览了四年的 Foreign Function & Memory API 在 22 进入 java.base：分配用 Arena、读写用 MemorySegment、布局用 ValueLayout，字符串拷贝有了 allocateFrom(String)。

import java.lang.foreign.Arena;
import java.lang.foreign.MemorySegment;
import java.lang.foreign.ValueLayout;
public class FFM22 {
  public static void main(String[] a) {
    try (Arena arena = Arena.ofConfined()) {
      MemorySegment greeting = arena.allocateFrom("hello ffi");
      System.out.println(greeting.getString(0));
      MemorySegment nums = arena.allocateFrom(ValueLayout.JAVA_INT, 7, 8, 9);
      System.out.println(nums.get(ValueLayout.JAVA_INT, 4));
      System.out.println("bytes=" + nums.byteSize());
    }
  }
}
// 运行输出：
// hello ffi
// 8
// bytes=12

✅ 实测通过（JDK 25）。要点：allocateFrom(String) 拷入并以 '\0' 结尾，getString(0) 按 C 字符串读回；allocateFrom(ValueLayout.JAVA_INT, 7, 8, 9) 直接按布局铺开 12 字节，偏移 4 处正是 8。

22.8 Launch Multi-File Source-Code Programs（JEP 458）

public class Main {

23.1 Primitive Types in Patterns, instanceof, and switch（JEP 455 · 首次预览）

把基元类型纳入模式匹配：o instanceof int i 会按「精确转换」做值检查（装箱拆箱、窄化安全），switch 的选择器也放开到 long/float/double/boolean，case true/false 与 case int i when ... 都能用。

public class PTP23 {
  public static void main(String[] a) {
    Object o = 42;
    if (o instanceof int i) {
      System.out.println("instanceof int " + i);
    }
    long big = 10_000_000_000L;
    String s = switch (big) {
      case 10_000_000_000L -> "ten billion";
      case long l when l > 0 -> "positive";
      default -> "other";
    };
    System.out.println(s);
    boolean ok = true;
    String t = switch (ok) {
      case true -> "yes";
      case false -> "no";
    };
    System.out.println(t);
    int n = 42;
    int over = 1000;
    System.out.println("42->byte=" + (n instanceof byte) + " 1000->byte=" + (over instanceof byte));
    System.out.println("bound=" + (n instanceof byte b ? b : -1));
  }
}
// 运行输出（javac --enable-preview --release 25；java --enable-preview）：
// instanceof int 42
// ten billion
// yes
// 42->byte=true 1000->byte=false
// bound=42

⚠️ 实测通过（JDK 25 预览特性，仍需 --enable-preview --release 25——25 对应 JEP 507 第三次预览，尚未转正）。要点：n instanceof byte 是值测试（42 装得下 → true，1000 装不下 → false），不是类型测试；布尔选择器的 case true/false 属于本特性范围，同样必须开预览。复现命令：javac --enable-preview --release 25 PTP23.java + java --enable-preview PTP23（java 不支持 --release）。

23.2 Module Import Declarations（JEP 476 · 预览）

一行 import module java.base; 相当于把该模块所有导出包里的一级类型都引进来：写小工具/示例代码时不必再逐个 import java.util.*。25（JEP 511）转正。

import module java.base;
public class MOD23 {
  public static void main(String[] a) {
    var list = List.of("a", "b", "c");
    System.out.println(list.getFirst() + " " + list.size());
    System.out.println(String.format("%04d-%s", 7, "ok"));
    var map = new java.util.HashMap<String, Integer>();
    System.out.println(map.isEmpty());
  }
}
// 运行输出：
// a 3
// 0007-ok
// true

✅ 实测通过（JDK 25，免预览）。List（java.util）与 String（java.lang）都没写单类型 import；HashMap 是特意用全限定名演示「模块导入只影响简单名解析」。

23.3 Implicitly Declared Classes（JEP 477 · 第三次预览）

第三次预览里隐式类已经很像「普通类去掉声明」：可以嵌套 record、可以定义泛型方法、main 仍是实例方法。25 的正式名是 Compact Source Files（JEP 512）。

record Result(String name, int score) {}
String join(java.util.List<?> items) {
  return items.stream().map(String::valueOf).reduce((a, b) -> a + "," + b).orElse("");
}
void main() {
  var r = new Result("ann", 99);
  System.out.println(r.name() + "=" + r.score());
  System.out.println(join(java.util.List.of("a", "b", "c")));
}
// 运行输出：
// ann=99
// a,b,c

✅ 实测通过（JDK 25，免预览）。顶层可以并排放 record、方法和 main——它们同属这个隐式声明的编译单元类。

23.4 Flexible Constructor Bodies（JEP 482 · 第二次预览）

在 22 的 JEP 447 基础上再进一步：prologue 里不但能打日志、算参数，还允许给本类自己的（无初始化器的）字段赋值——从而让父类构造器回调被重写方法时，读到的是子类的真实值而不是 0/null。

class Super23 {
  Super23() { overridden(); }
  void overridden() { System.out.println("hello"); }
}
class Sub23 extends Super23 {
  final int x;
  Sub23(int x) {
    this.x = x;
    super();
  }
  @Override void overridden() { System.out.println("x=" + x); }
}
public class FCB23 {
  public static void main(String[] a) {
    new Sub23(42);
    Sub23 s = new Sub23(7);
    System.out.println("field=" + s.x);
  }
}
// 运行输出：
// x=42
// x=7
// field=7

✅ 实测通过（JDK 25，免预览——JEP 513 已在 25 转正；23 当年需 --enable-preview --release 23）。对照 JEP 482 的经典反例：new Sub23(42) 若按老规则，父类回调会打印 x=0（子类字段还没赋值）；现在 prologue 先 this.x = x，输出变成 x=42。注意 prologue 里能写不能读本实例字段，也不能调用本实例方法。

23.5 Markdown Documentation Comments（JEP 467 · 正式）

文档注释可以直接写 Markdown：新形态是逐行 /// 开头的注释（不是在 /** ... */ 里塞 ```markdown 围栏），空行分段、- 列表、反引号行内代码、# 标题、引用链接 [java.util.List] 都可用，且与 HTML、@ 标签混写。

/// # Markdown Demo
///
/// A short list of steps:
///
///   1. write the comment
///   2. run `javadoc`

public class MDJ23 {

  ///
  /// @param x any number
  /// @return `x` multiplied by two

  public static void main(String[] a) {
    System.out.println(new MDJ23().twice(21));
  }
}
// 运行输出：42

✅ javac/java 实测通过（JDK 25；JEP 467 在 23 就是正式特性，免预览）。

23.6 Stream Gatherers 第二次预览（JEP 473）

第二次预览主要修订 Windowing/Fold 等的语义细节；24 转正。换个内置 gatherer 复测。

import java.util.stream.Gatherers;
import java.util.stream.Stream;
public class GAT23 {
  public static void main(String[] a) {
    var sliding = Stream.of(1, 2, 3, 4, 5).gather(Gatherers.windowSliding(2)).toList();
    System.out.println(sliding);
    var joined = Stream.of("a", "b", "c").gather(Gatherers.fold(() -> "", (acc, s) -> acc + s)).toList();
    System.out.println(joined);
    System.out.println(Stream.of(1, 2, 3).gather(Gatherers.windowFixed(5)).toList());
  }
}
// 运行输出：
// [[1, 2], [2, 3], [3, 4], [4, 5]]
// [abc]
// [[1, 2, 3]]

✅ 实测通过（JDK 25）。要点：windowSliding 步长恒为 1（窗口重叠）；windowFixed(5) 遇到只有 3 个元素的流时，最后一个「不满的窗口」照样输出。

23.7 Class-File API 第二次预览（JEP 466）

第二次预览把「生成」这一半补全：ClassFile.of().build(ClassDesc, builder) 能凭空造 class 字节，配合 MethodHandles.Lookup.defineClass 直接加载。24（JEP 484）转正。

import java.lang.classfile.ClassFile;
import java.lang.classfile.ClassModel;
import java.lang.constant.ClassDesc;
import java.lang.constant.MethodTypeDesc;
import java.lang.invoke.MethodHandles;
import static java.lang.constant.ConstantDescs.CD_int;
public class CF23 {
  public static void main(String[] a) throws Throwable {
    byte[] bytes = ClassFile.of().build(ClassDesc.of("Gen"), clb ->
        clb.withMethod("twice", MethodTypeDesc.of(CD_int, CD_int),
            ClassFile.ACC_PUBLIC | ClassFile.ACC_STATIC,
            mb -> mb.withCode(cb -> cb.iload(0).iconst_2().imul().ireturn())));
    System.out.println("built=" + bytes.length + " bytes");
    Class<?> gen = MethodHandles.lookup().defineClass(bytes);
    System.out.println("twice(21)=" + gen.getMethod("twice", int.class).invoke(null, 21));
    ClassModel back = ClassFile.of().parse(bytes);
    System.out.println("methods=" + back.methods().size());
  }
}
// 运行输出：
// built=107 bytes
// twice(21)=42
// methods=1

✅ 实测通过（JDK 25）。这条把 22.6（读）与 23.7（写）串成闭环：build → defineClass 动态加载 → 反射调用 → 再 parse 回读。字节码只有 5 条指令（iload/iconst_2/imul/ireturn），是「API 直接产出可执行字节」的最小证据。

23.8 IO 简写类：java.io.IO（23 预览）→ java.lang.IO（25）

勘误：包名与版本，两个方向都要澄清

素材写的是 java.io.IO、用户侧勘误主张「应为 java.lang.IO」。按 JEP 477 正文（「The new class java.io.IO is a preview API in JDK 23」）与 JDK 23/24 官方 API 文档：23 的确新增了 java.io.IO（预览，基于 System.console()，方法为 println(Object)/print(Object)/readln(String)，Since: 23）。而本机 JDK 25 实测：java.io.IO 已不存在（javap java.io.IO → 找不到类），取而代之的是 java.lang.IO（JDK 25 源码标注 @since 25，直接写 System.out/System.in，不再依赖控制台对象）。所以：说「23 有 java.io.IO」是对的，说「25 用 java.lang.IO」也是对的，二者是两个不同时点的类，别混为一谈。

本页示例按 25 现行形态（java.lang.IO）给出：

import java.lang.IO;
public class IO23 {
  public static void main(String[] a) {
    IO.println("hello java.lang.IO");
    IO.println(42);
    IO.print("no newline: ");
    IO.println(true);
  }
}
// 运行输出：
// hello java.lang.IO
// 42
// no newline: true

✅ 实测通过（JDK 25，正式 API 免预览）。定位是「给隐式类/入门程序的最短 I/O」：IO.println(...) ≈ System.out.println(...)，IO.readln(...) 读 System.in；23 的 java.io.IO 版本因依赖 System.console()（无控制台时抛 IOError）语义不同，属预览形态。
