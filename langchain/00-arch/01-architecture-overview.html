二、Runnable 类层次结构

LangChain 的核心抽象是 Runnable<Input, Output>，所有可运行组件都继承自它。

关于泛型参数

完整签名是 Runnable<Input, Output>，为适配 Mermaid 类图语法并保证渲染稳定，图中泛型参数做了简化（仅保留首参 Input）。实际使用时请以 Python 源码签名为准。

五种模式的核心差异

Supervisor 是集中式调度，Handoffs 是控制权转移，Router 是无状态分类分发，Skills 是按需加载能力，Custom Workflow 则是完全自由编排。选择哪种，取决于「谁负责协调」与「协调是否集中」。

六、核心数据流

sequenceDiagram participant User as 👤 用户 participant Agent as 🤖 Agent participant Model as 🧠 LLM 模型 participant Tool as 🔧 工具 participant State as 📊 StateGraph participant Memory as 💾 Checkpoint User->>State: 输入问题 (HumanMessage) State->>Agent: 分发到 Agent 节点 loop Agent 思考-行动循环 Agent->>Model: 发送消息 + 工具定义 Model-->>Agent: 返回 AI 回复 / 工具调用请求 alt 需要调用工具 Agent->>Tool: 执行工具调用 Tool-->>Agent: 返回 ToolMessage Agent->>Model: 发送工具结果 Model-->>Agent: 返回最终回复 end end Agent-->>State: 返回结果 (AIMessage) State->>Memory: 保存 Checkpoint State-->>User: 返回最终回答

八、技术栈关系

层级技术作用
编排引擎 LangGraph StateGraph 构建有状态工作流，条件路由，Checkpoint
Agent 框架 LangChain create_agent() 创建智能体，绑定工具和系统提示
模型后端 ChatOpenAI (兼容) DeepSeek / OpenAI / 本地模型
向量存储 ChromaDB / FAISS 向量检索、混合检索、元数据过滤
嵌入模型 DashScope text-embedding-v3 文本向量化
MCP 协议 langchain-mcp-adapters 多服务器工具集成
UI 框架 Gradio ChatInterface 交互式问答界面
检查点 InMemorySaver 会话状态持久化
生产环境提示

上表中的 InMemorySaver 仅适用于本地开发与单元测试。生产环境请替换为持久化检查点（如 PostgreSQL / Redis Saver），否则进程重启即丢失全部会话状态。
