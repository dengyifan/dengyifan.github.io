第2课：读取记忆 — state 与 context 的区别和用法

📖 前置：第1课 ToolRuntime ⏱ 预计 30 分钟 🎯 L2

上一课讲了 ToolRuntime 是什么、怎么注入的。本课聚焦：用 ToolRuntime 读什么、怎么读，state 和 context 到底有什么区别？

2.1 读取 state：访问当前状态

代码示例：

class CustomState(AgentState):
    user_id: str

@tool
def get_user_info(runtime: ToolRuntime) -> str:
    """look up user info"""
    user_id = runtime.state["user_id"]   # 读取自定义状态字段
    return "User is John Smith" if user_id == "user_123" else "User is unknown"

agent = create_agent(model, tools=[get_user_info], state_schema=CustomState)
result = agent.invoke({
    "messages": "look up user information",
    "user_id": "user_123"   # 传入自定义状态
})

关键点：runtime.state 是一个 dict-like 对象，含有 AgentState 的所有字段（包括内置的 messages 和自定义的 user_id）。

state 里有什么

字段来源说明
messagesAgentState 内置对话历史消息列表
{自定义字段}state_schema 扩展如 user_id、preferences 等
state 的本质：state 是图的运行状态——它会随着工具执行、节点输出而动态变化。工具可以读它，也可以写它（下节课讲）。state 的典型用途：跨轮次共享信息、在工具间传递中间结果。

2.2 读取 context：访问运行时上下文

看 context 的用法：

class CustomContext(BaseModel):
    user_id: str

@tool
def update_user_info(runtime: ToolRuntime[CustomContext, CustomState]) -> Command:
    """look up and update user info."""
    user_id = runtime.context.user_id   # 从 context 读取
    user_name = "John Smith" if user_id == "user_123" else "Unknown"
    return Command(update={"user_name": user_name, ...})

agent = create_agent(
    model, tools=[update_user_info, greet],
    state_schema=CustomState,
    context_schema=CustomContext   # 声明 context 类型
)
result = agent.invoke(
    {"messages": [{"role": "user", "content": "greet the user"}]},
    context=CustomContext(user_id="user_123")   # 传入 context（与 invoke 参数同级）
)

注意两个关键区别：

  1. context 通过 context_schema 声明，在 invoke 时作为独立参数传入，而不是放在 state 字典里
  2. runtime.context 是 类型安全 的（通过泛型 ToolRuntime[CustomContext, CustomState]），IDE 可以有代码补全

判断口诀：如果这个信息会随着对话过程变化（比如"用户刚才说了什么"、"工具查到了什么"），放 state。如果它在整个对话中不变、只是外部传入的配置（比如"当前用户是谁"、"用哪个 API key"），放 context。

2.4 为什么分 state 和 context？

这是面试中常被追问的问题。答案分三层：

1. 职责分离：state 是对话内的（对话结束后就没意义了），context 是对话外的（不管谁和 agent 对话，这个用户 ID 都固定）。混在一起会让状态管理变得混乱。
2. 持久化策略不同：state 需要持久化（多轮对话恢复），context 不需要（每次调用都重新传入）。如果 context 也持久化，修改一个用户 ID 需要清理所有历史 checkpoint，这是灾难性的。
3. 安全性：context 可能包含敏感信息（如 API key）。这些信息不应该出现在 state 中——state 会被 Checkpointer 持久化到数据库，增加了泄露风险。context 只在内存中，用完即丢弃。

2.5 扩展：在 Middleware 中读取记忆

除了在工具中读取，也可以在 Middleware 中读取 state 和 context，用于动态生成系统提示词：

from langchain.agents.middleware import dynamic_prompt, ModelRequest

@dynamic_prompt
def dynamic_system_prompt(request: ModelRequest) -> str:
    user_name = request.runtime.context["user_name"]   # 从 context 读取
    system_prompt = f"You are a helpful assistant. Address the user as {user_name}."
    return system_prompt

注意这里用的是 request.runtime（Runtime，不是 ToolRuntime），因为 Middleware 不在工具执行上下文中。这是第 4 课要深入讲的区别。

2.6 从 Java 视角看

Java 视角对照

state ↔ 类似 HttpSession：跨请求共享数据，会随着用户操作而变化。但 HttpSession 是服务端存储，而 LangGraph 的 state 由 Checkpointer 持久化到数据库。

context ↔ 类似 ThreadLocal 或 Request Header：每次请求独立传入，请求期间不变，请求结束后丢弃。但 context 比 ThreadLocal 更安全——ThreadLocal 可能导致内存泄漏，而 context 的生命周期由框架显式管理。

关键区别：Java 的 HttpSession 和 Request Header 是 Servlet 容器层面的概念，不区分"对话内状态"和"对话外配置"。LangGraph 的 state/context 分离是对 Agent 场景的针对性设计——对话状态需要持久化，外部配置不需要。

2.7 本课小结

你怎么读代码
读 state 字段runtime.state["user_id"] 或 runtime.state["messages"]
读 context 字段runtime.context.user_id（泛型安全）或 runtime.context["user_name"]
