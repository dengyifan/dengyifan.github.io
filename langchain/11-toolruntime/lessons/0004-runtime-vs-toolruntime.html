4.1 两个 Runtime：各自的定位

源码中的关键注释（tool_node.py L1663-1684）：

This is distinct from Runtime (from langgraph.runtime), which is injected into graph nodes and middleware. ToolRuntime includes additional tool-specific attributes like config, state, and tool_call_id that Runtime does not have.

记忆口诀：Runtime 是「图节点级别」的上下文，ToolRuntime 是「工具调用级别」的上下文。ToolRuntime 继承了 Runtime，外加三个特有字段：state（当前状态）、tool_call_id（调用 ID）、config（执行配置）。

4.2 为什么区分两个 Runtime？

1. 职责不同：图节点（Middleware）不需要知道「当前是哪个工具调用」，它关心的是「整个图执行到哪了」。工具则相反——它需要精确知道当前调用的 tool_call_id 和 state。
2. 注入时机不同：Runtime 在图节点启动时注入（一次），ToolRuntime 在每次工具调用时构造（多次）。一个节点可能触发多次工具调用，每次都需要独立的 ToolRuntime。
3. 类型安全：用独立的类区分，避免图节点误用工具专属字段（如 tool_call_id），编译期即可发现类型错误。

4.3 emit_output_delta：流式工具输出

这是 ToolRuntime 独有的方法，Runtime 没有。源码（tool_node.py L1732-1742）：

def emit_output_delta(self, delta: Any) -> None:
    """Stream a partial output chunk on the `tools` stream channel.

    Reads the per-tool-call writer that `StreamToolCallHandler`
    installs on a ContextVar at `on_tool_start` and forwards `delta`
    through it. Silent no-op when the graph was not run with
    `"tools"` in `stream_mode` (no writer is set), so tool authors
    can leave `emit_output_delta` calls in place without gating
    them on stream mode.
    """

使用示例

@tool
def long_running_tool(runtime: ToolRuntime) -> str:
    """A tool that does multiple steps."""
    runtime.emit_output_delta({"progress": "查询中..."})   # 流式推送中间状态
    result = do_step1()
    runtime.emit_output_delta({"progress": "处理中..."})   # 继续推送
    result = do_step2(result)
    return result

底层机制

sequenceDiagram participant Graph as Graph 引擎 participant Handler as StreamToolCallHandler participant CV as ContextVar participant Tool as 工具函数 Graph->>Handler: on_tool_start(tool_call) Handler->>CV: 安装 writer 到 ContextVar Tool->>Tool: emit_output_delta(delta) Tool->>CV: 读取 writer Tool->>Handler: 通过 writer 推送 delta Handler->>Graph: 流式输出到 tools channel Tool->>Handler: on_tool_end(tool_call) Handler->>CV: 清理 writer
设计巧妙之处：emit_output_delta 通过 ContextVar 共享 writer，而不是作为参数传入。这样工具作者不需要关心流式模式是否开启——如果没开启 stream_mode="tools"，ContextVar 里没有 writer，方法静默无操作（no-op），不会报错。
注意：emit_output_delta 推送的是 部分结果，不是最终返回。最终返回值（str / ToolMessage / Command）仍然需要通过正常 return 返回。这个方法是「带外通道」，走的是 tools 流通道，与主返回值走不同的管道。

4.4 从 Java 视角看

Java 视角对照

Runtime vs ToolRuntime ↔ 类似 Servlet 的 ServletContext vs HttpServletRequest：ServletContext 是应用级（类似 Runtime 注入到整个图节点），HttpServletRequest 是请求级（类似 ToolRuntime 每次工具调用构造）。

ContextVar ↔ 类似 Java 的 ThreadLocal：在异步/协程环境中安全地共享上下文，而不需要显式传参。但 Python 的 ContextVar 比 ThreadLocal 更现代——它支持 asyncio 的协程隔离，不会出现 ThreadLocal 在协程复用线程时的串扰问题。
