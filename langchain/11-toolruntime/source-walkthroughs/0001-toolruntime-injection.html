3.1 ToolRuntime 类定义 (L1663-1742)

class ToolRuntime(_DirectlyInjectedToolArg, Generic[ContextT, StateT]):
    """Runtime context automatically injected into tools.

    This is distinct from `Runtime` (from `langgraph.runtime`), which is injected
    into graph nodes and middleware. `ToolRuntime` includes additional tool-specific
    attributes like `config`, `state`, and `tool_call_id` that `Runtime` does not
    have.
    """

    state: StateT
    context: ContextT
    config: RunnableConfig
    stream_writer: StreamWriter
    tool_call_id: str | None
    store: BaseStore | None
    tools: list[BaseTool] = field(default_factory=list)
    execution_info: ExecutionInfo | None = None
    server_info: ServerInfo | None = None

    def emit_output_delta(self, delta: Any) -> None:
        """Stream a partial output chunk on the `tools` stream channel.

        Reads the per-tool-call writer that `StreamToolCallHandler`
        installs on a ContextVar at `on_tool_start` and forwards `delta`
        through it. Silent no-op when the graph was not run with
        `"tools"` in `stream_mode` ...
        """

分析：

  • L1663：继承 _DirectlyInjectedToolArg — 这是一个标记类，用于类型检测。在 _get_all_injected_args 中通过 _is_injected_arg_type 判断参数是否需要注入。
  • L1665-1671：注释明确区分了 ToolRuntime 和 Runtime 的差异，强调 state、tool_call_id、config 是工具特有的。
  • L1722-1730：字段定义。注意 store 和 context 与 Runtime 共享同一个实例引用（不是拷贝），所以修改 store 会影响整个图。
  • L1732-1742：emit_output_delta 通过 ContextVar 获取 writer，设计成「no-op when no writer」——工具作者可以随意调用，不用担心流式模式是否开启。

3.2 ToolNode._func 构造 ToolRuntime (L793-826)

def _func(self, input, config, runtime):
    tool_calls, input_type = self._parse_input(input)
    config_list = get_config_list(config, len(tool_calls))

    # Construct ToolRuntime instances at the top level for each tool call
    tool_runtimes = []
    for call, cfg in zip(tool_calls, config_list, strict=False):
        state = self._extract_state(input, cfg)
        tool_runtime = ToolRuntime(
            state=state,
            tool_call_id=call["id"],
            config=cfg,
            context=runtime.context,           # 继承自 Runtime
            store=runtime.store,               # 继承自 Runtime
            stream_writer=runtime.stream_writer, # 继承自 Runtime
            tools=list(self.tools_by_name.values()),
            execution_info=runtime.execution_info,
            server_info=runtime.server_info,
        )
        tool_runtimes.append(tool_runtime)

    with get_executor_for_config(config) as executor:
        outputs = list(
            executor.map(self._run_one, tool_calls, input_types, tool_runtimes)
        )
    return self._combine_tool_outputs(outputs, input_type)

分析：

  • L803-817：每个 tool call 构造一个独立的 ToolRuntime。注意 context、store、stream_writer 都是从外层 runtime（图节点级 Runtime）继承的，而 state 和 tool_call_id 是工具特有的。
  • L821-824：使用 executor.map 并行执行多个工具调用。这就是「并行执行时写入冲突」的根本原因。

3.3 _inject_tool_args 注入参数 (L1315-1430)

def _inject_tool_args(self, tool_call, tool_runtime, tool=None):
    # ...docstring...
    injected = self._injected_args.get(tool_call["name"])
    if not injected and tool is not None:
        injected = _get_all_injected_args(tool)  # 动态工具：运行时扫描
    if not injected:
        return tool_call

    tool_call_copy = copy(tool_call)
    injected_args = {}

    # Inject state
    if injected.state:
        state = tool_runtime.state
        # ... 提取 state 字段 ...

    # Inject store
    if injected.store:
        if tool_runtime.store is None:
            raise ValueError("Cannot inject store into tools...")
        injected_args[injected.store] = tool_runtime.store

    # Inject runtime
    if injected.runtime:
        injected_args[injected.runtime] = tool_runtime

    # Strip any caller-supplied values for injected args
    stripped_args = {
        k: v
        for k, v in tool_call_copy["args"].items()
        if k not in injected.all_injected_keys
    }
    tool_call_copy["args"] = {**stripped_args, **injected_args}
    return tool_call_copy

分析：

  • L1354-1361：优先从初始化时缓存的 _injected_args 获取，动态工具运行时扫描。这是性能优化——避免每次调用都扫描签名。
  • L1366-1395：注入 state。支持 dict 和 BaseModel 两种 state 格式，还处理了 list state 的特殊情况。
  • L1407-1415：注入 store 时，如果 store 为 None 则抛异常。所以工具如果声明了 InjectedStore，必须编译图时提供 store。
  • L1417-1419：注入 runtime——直接把整个 ToolRuntime 实例赋给参数。
  • L1421-1429：这是防伪造的核心。先剥离所有模型提供的注入键（all_injected_keys），再填回系统构造的受信任值。模型即便在 ToolCall.args 里塞了 runtime: {...}，也会被剥离。

3.4 _get_all_injected_args 扫描签名 (L1967-2021)

def _get_all_injected_args(tool: BaseTool) -> _InjectedArgs:
    full_schema = tool.get_input_schema()
    schema_annotations = get_all_basemodel_annotations(full_schema)
    func = getattr(tool, "func", None) or getattr(tool, "coroutine", None)
    func_annotations = get_type_hints(func, include_extras=True) if func else {}
    all_annotations = {**func_annotations, **schema_annotations}

    for name, type_ in all_annotations.items():
        # 1. 参数名为 "runtime" → 注入 ToolRuntime
        if name == "runtime":
            runtime_arg = name
        # 2. 标注了 InjectedState → 注入 state
        if state_inj := _get_injection_from_type(type_, InjectedState):
            state_args[name] = state_inj.field
        # 3. 标注了 InjectedStore → 注入 store
        if _get_injection_from_type(type_, InjectedStore):
            store_arg = name
        # 4. 标注了 ToolRuntime → 注入 ToolRuntime
        if _get_injection_from_type(type_, ToolRuntime):
            ...

分析：

  • L1980-1988：从两个来源合并注解：schema 的 pydantic 注解 + 函数签名的 type hints。schema 优先——所以 pydantic 的 Field 描述会覆盖函数签名。
  • L1997-2021：遍历所有注解，识别三类注入参数。关键逻辑在 _get_injection_from_type（L1937-1964），它通过 get_args(type_) 解析泛型参数，检查是否匹配 InjectedState / InjectedStore / ToolRuntime。
  • L2003：name == "runtime" 是唯一不依赖类型标注的注入判断——只要参数名叫 runtime，就注入 ToolRuntime。如果参数名不是 runtime 但标注了 ToolRuntime，也能注入（L2021）。

4. 关键设计决策

决策为什么代价
每个 tool call 构造独立 ToolRuntime保证并行执行时 state 隔离，避免竞态多次构造有轻微开销（但可忽略）
ContextVar 承载 stream writer避免显式传参，工具作者无感知调试时 ContextVar 的隐式依赖难以追踪
剥离 + 填回注入参数防止 LLM 伪造注入值，安全基线增加了注入逻辑的复杂度
缓存 injected_args 而非每次扫描性能优化，避免重复解析注解动态工具需要额外处理（L1356-1359）
