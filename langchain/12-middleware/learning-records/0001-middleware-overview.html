Non-obvious insights captured

  1. Middleware is graph-native, not a runtime. Hooks are compiled into LangGraph nodes/edges. The most common misconception is treating middleware as "interceptors that run before/after" when they are actually the structural nodes of the agent's execution graph.
  2. The agent loop iterates per model response, not per tool call. If the LLM returns 3 tool_calls in one response, all 3 execute in parallel in a single superstep. The loop only iterates again after those results trigger a new model call.
  3. jump_to is EphemeralValue + PrivateStateAttr. It resets after each superstep and is hidden from I/O schemas. This is why you must (a) set it each time you want a jump, and (b) declare can_jump_to at compile time to build the conditional edge.
  4. ModelRequest immutability is the composition enabler. request.override() returns a new instance via dataclasses.replace() (shallow). Direct assignment is deprecated via __setattr__. This prevents middleware side-effects from leaking into each other.
  5. GraphBubbleUp must always propagate. Any except Exception in a wrap hook must re-raise GraphBubbleUp, or it swallows LangGraph control-flow (interrupts, parent Commands) and breaks human-in-the-loop.

Key call chains

  • create_agent → decode middleware → type() creates AgentMiddleware subclass → compile into StateGraph → .compile().
  • ModelRetryMiddleware.wrap_model_call: loop range(max_retries+1) → handler(request) → should_retry_exception → calculate_delay (backoff + jitter) → _handle_failure.
