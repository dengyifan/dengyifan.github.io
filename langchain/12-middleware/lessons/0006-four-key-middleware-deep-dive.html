PIIMiddleware — 个人敏感信息处理

L1 概念

防止敏感信息流出，四策略：block 拦截、redact 替换、mask 掩码、hash 哈希。它在 before_model 阶段拦截，识别消息中的 PII 实体（邮箱、信用卡、手机号等），按策略改写后再交给模型。

L2 原理 + 伪代码

def process_text(text, fields, strategy):
    results = analyzer.analyze(text, fields)   # presidio NER 识别实体及 span
    for r in results:
        if strategy == "block":   return BLOCK_REQUEST           # 直接拦截
        elif strategy == "redact": text = text.replace(r, "[REDACTED]")
        elif strategy == "mask":   text = partial_mask(r)        # 保留首尾
        elif strategy == "hash":   text = sha256(r.text)         # 不可逆哈希
    return text

L3 源码层

核心类位于 langchain/agents/middleware/pii.py，继承 BaseMiddleware，核心在 before_model。完整结构拆解：

# langchain/agents/middleware/pii.py（关键结构）
from langchain_core.messages import BaseMessage, HumanMessage
from .base import BaseMiddleware

class PIIMiddleware(BaseMiddleware):
    def __init__(self, *fields, strategy="block",
                 pii_types=None, analyzer=None, anonymizer=None):
        self.fields = fields
        self.strategy = strategy
        self.pii_types = pii_types
        self.analyzer = analyzer or PIIAnalyzer()      # presidio-analyzer
        self.anonymizer = anonymizer or PIIAnonymizer() # presidio-anonymizer

    def before_model(self, state):
        messages = state["messages"]
        return {"messages": [self._process_msg(m) for m in messages]}

    def _process_msg(self, msg):
        if not hasattr(msg, "content") or not msg.content:
            return msg
        processed = self._sanitize(msg.content)
        return msg.model_copy(update={"content": processed})

    def _sanitize(self, text):
        entities = self.analyzer.analyze(text, self.pii_types or self.fields)
        if self.strategy == "block" and entities:
            raise PIISensitiveDataError("Blocked: PII detected")
        return self.anonymizer.anonymize(text, entities, self.strategy)

关键要点：block 策略命中即抛异常中断；redact/mask/hash 分别对应 ReplaceEntity / MaskEntity / HashEntity 操作。返回的仍是 HumanMessage 类型，用 model_copy 保持原有类型不破坏下游。

完整代码示例

from langchain.agents import create_agent
from langchain.agents.middleware import PIIMiddleware
from langchain_core.tools import tool

@tool
def send_email(to: str, body: str):
    """发送邮件（含敏感信息）"""
    return f"Sending to {to}: {body}"

agent = create_agent(
    model="gpt-4o",
    tools=[send_email],
    middleware=[
        PIIMiddleware("email", "phone", strategy="redact"),
    ],
)

result = agent.invoke({"messages": [{"role": "user",
    "content": "请把结果发到 test@example.com，我手机 13800138000"}]})
# 发送工具收到的 body 中的邮箱/手机号已被替换

graph LR A["用户输入消息"] --> B{"含 PII?"} B -- "否" --> C["原样传给模型"] B -- "是" --> D["presidio 识别实体"] D --> E{"strategy?"} E -- "block" --> F["抛异常中断"] E -- "redact" --> G["替换为 [REDACTED]"] E -- "mask" --> H["部分掩码保留首尾"] E -- "hash" --> I["哈希替换"] G --> J["传给模型"] H --> J I --> J F --> K["请求终止"]
依赖说明

依赖 presidio-analyzer / anonymizer，中文识别准确率需验证；对长文本每轮都跑 NER，token 大时开销明显。

注意事项

block 会中断整个请求，需搭配 HumanInTheLoop 才能「先问再放行」。

HumanInTheLoopMiddleware — 人工审批

L1 概念

敏感工具（付款、删库、发邮件）执行前暂停，生成 HumanApproval 中断事件，外部 UI 批准后才继续执行。

L2 原理 + 伪代码

def before_tool(model_state, tool_name, interrupt_on):
    if tool_name in interrupt_on:
        decision = interrupt(HumanApproval(tool_name, args))
        if decision.rejected: return skip_tool()
    return proceed()

L3 源码层

核心类位于 langchain/agents/middleware/human_in_the_loop.py。通过 wrap_tool_call 在工具执行前注入中断；恢复依赖 LangGraph 的 interrupt() 原语与 checkpointer。

# langchain/agents/middleware/human_in_the_loop.py（关键结构）
from langgraph.types import interrupt
from langchain_core.messages import ToolMessage
from .base import BaseMiddleware

class HumanInTheLoopMiddleware(BaseMiddleware):
    def __init__(self, interrupt_on=None, on_user_approve=None):
        self.interrupt_on = interrupt_on or set()
        self.on_user_approve = on_user_approve

    def wrap_tool_call(self, name, func):
        if name not in self.interrupt_on:
            return func
        def wrapper(*args, **kwargs):
            approval = interrupt(HumanApproval(tool_name=name, args=kwargs))
            if not approval.approved:
                return ToolMessage(content="User rejected", tool_call_id=...)
            result = func(*args, **kwargs)
            return result
        return wrapper

    def wrap_model_call(self, func):
        return func

关键机制：interrupt() 是 LangGraph 的中断原语，它暂停图执行、保存状态，等待外部 Command(resume=...) 恢复。恢复时必须携带 thread_id + checkpointer，否则断点丢失。

完整代码示例

from langchain.agents import create_agent
from langchain.agents.middleware import HumanInTheLoopMiddleware
from langchain_core.tools import tool

@tool
def delete_user(user_id: str):
    """删除用户（敏感操作）"""
    return f"Deleted {user_id}"

agent = create_agent(
    model="gpt-4o",
    tools=[delete_user],
    middleware=[
        HumanInTheLoopMiddleware(interrupt_on={"delete_user"}),
    ],
)

config = {"configurable": {"thread_id": "user-123"}}

for event in agent.stream({"messages": [{"role": "user", "content": "删掉用户 u42"}]}, config):
    if "interrupt" in event:
        print("等待人工审批...", event["interrupt"]["value"])

from langgraph.types import Command
for event in agent.stream(Command(resume={"approved": True}), config):
    print(event)

graph LR A["模型产生 tool_calls"] --> B{"tool 在 interrupt_on?"} B -- "否" --> C["直接执行工具"] B -- "是" --> D["interrupt 暂停"] D --> E["外部 UI 展示审批"] E --> F{"用户批准?"} F -- "否" --> G["跳过工具 写拒绝 ToolMessage"] F -- "是" --> H["恢复执行工具"] H --> I["返回结果"] G --> I C --> I
注意事项

恢复依赖 thread_id + checkpointer，否则断点丢失；审批卡死会一直挂起，需超时降级。

TodoListMiddleware — 任务规划

L1 概念

在模型前注入待办清单 SystemMessage，维持多步任务规划，让 Agent 不丢失目标。

L2 原理 + 伪代码

def before_model(state):
    todos = state.get("todos", [])
    sys_msg = SystemMessage(render_todo_prompt(todos))
    return {"messages": [sys_msg] + state["messages"]}

L3 源码层

核心类位于 langchain/agents/middleware/todo_list.py。它在每次模型调用前注入 SystemMessage，同时提供工具让模型更新待办。

# langchain/agents/middleware/todo_list.py（关键结构）
from langchain_core.messages import SystemMessage, ToolMessage
from .base import BaseMiddleware

TODO_PROMPT = """You are maintaining a TODO list for this task.
Current todos: {todos}
Use the update_todos tool to add/complete/remove items as you progress.
"""

class TodoListMiddleware(BaseMiddleware):
    def __init__(self):
        self._todos = []

    def before_model(self, state):
        todos = state.get("todos", self._todos)
        message = SystemMessage(content=TODO_PROMPT.format(todos=todos))
        return {"messages": [message] + state["messages"]}

    def after_model(self, state):
        return state

    def update_todos(self, todos):
        self._todos = todos
        return f"Todos updated: {todos}"

关键点：待办清单以 SystemMessage 注入，系统级优先级高、不占用户可见内容；模型通过工具回调更新清单，形成闭环。

完整代码示例

from langchain.agents import create_agent
from langchain.agents.middleware import TodoListMiddleware
from langchain_core.tools import tool

@tool
def search_docs(query: str):
    """搜索文档"""
    return f"results for {query}"

@tool
def update_todos(todos: list):
    """更新任务清单"""
    return f"Todos set to {todos}"

agent = create_agent(
    model="gpt-4o",
    tools=[search_docs, update_todos],
    middleware=[TodoListMiddleware()],
)

result = agent.invoke({"messages": [{"role": "user",
    "content": "调研 LangChain 的 5 个特性，并写出报告"}]})
print(result["messages"][-1].content)

ContextEditingMiddleware — 上下文修剪

L1 概念

按 token 预算修剪/摘要/清除消息，防止上下文溢出。常用在 after_model 阶段，工具结果产生后立即处理。

L2 原理 + 伪代码

def after_model(state):
    messages = state["messages"]
    while token_count(messages) > max_tokens:
        messages = apply_edit(messages, edits)
    return {"messages": messages}

L3 源码层

核心类位于 langchain/agents/middleware/context_editing.py。核心是「编辑器」组合：TrimmingEdit（按 token 裁剪）、SummarizationEdit（LLM 摘要）、ClearEdit（清除）。

# langchain/agents/middleware/context_editing.py（关键结构）
from langchain_core.messages import BaseMessage
from .base import BaseMiddleware

class ContextEditingMiddleware(BaseMiddleware):
    def __init__(self, edits=None, token_count_method="disabled",
                 max_tokens=None):
        self.edits = edits or []
        self.token_counter = build_counter(token_count_method)
        self.max_tokens = max_tokens

    def after_model(self, state):
        messages = state["messages"]
        if self._is_over_limit(messages):
            messages = self._apply_edits(messages)
        return {"messages": messages}

    def _is_over_limit(self, messages):
        total = sum(self.token_counter.count(m) for m in messages)
        return total > self.max_tokens

    def _apply_edits(self, messages):
        for edit in self.edits:
            messages = edit.apply(messages)
        return messages

class TrimmingEdit:
    def __init__(self, token_count, reserved_tokens=0, max_tokens=None):
        ...
    def apply(self, messages):
        while self._total_tokens(messages) > self.max_tokens:
            messages.pop(0)
        return messages

class SummarizationEdit:
    def __init__(self, model, token_count, trigger, keep):
        ...
    def apply(self, messages):
        return summarized_messages

关键点：token_count_method 可配置 tiktoken / character / disabled，不同计数方式结果不同。修剪会删除旧消息，需保证 tool_call_id 对应关系不断裂。

完整代码示例

from langchain.agents import create_agent
from langchain.agents.middleware import ContextEditingMiddleware, TrimmingEdit, SummarizationEdit
from langchain_core.tools import tool

@tool
def get_large_data(query: str):
    """返回大量数据"""
    return "x" * 10000

edits = [
    SummarizationEdit(model="gpt-4o-mini", token_count_method="tiktoken",
                      trigger=("fraction", 0.8), keep=5),
    TrimmingEdit(token_count_method="tiktoken", max_tokens=6000),
]

agent = create_agent(
    model="gpt-4o",
    tools=[get_large_data],
    middleware=[
        ContextEditingMiddleware(edits=edits, token_count_method="tiktoken"),
    ],
)

result = agent.invoke({"messages": [{"role": "user", "content": "拉取大数据并总结"}]})
print(result["messages"][-1].content)

面试题库

PII

  • Q: 四种策略区别？ A: block拦截/redact替换/mask掩码/hash哈希，粒度到字段。
  • Q: 为什么用 presidio？ A: 基于 NER 的实体识别，比正则更鲁棒，但中文需校准。
  • Q: block 命中后如何不中断流程？ A: 搭配 HumanInTheLoop 先问后放行，或降级为 redact。

HumanInTheLoop

  • Q: interrupt 与普通 return 区别？ A: interrupt 暂停图执行、保留状态、需外部恢复。
  • Q: 并行工具如何审批？ A: 逐个 interrupt_on，或聚合为单次审批。
  • Q: 恢复必须什么？ A: thread_id + checkpointer，否则断点丢失。

TodoList

  • Q: 为何用 SystemMessage？ A: 系统级指令，优先级高且不占用户可见内容。
  • Q: 模型不更新 todo 怎么办？ A: 可提供 update_todos 工具强制回调，或定期重注入。

ContextEditing

  • Q: 为何 after_model 修剪？ A: 工具结果最新产生，届时才能准确计数。
  • Q: token 超限崩溃如何降级？ A: 提前触发修剪 + 错误重试 + 设置 budget 上限。
  • Q: 修剪导致 tool_call_id 断裂？ A: 需保证被删消息的关联 ToolMessage 也同步处理，或用 Summarization 而非硬删。
