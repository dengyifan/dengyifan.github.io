分支优先级

分支优先级说明
stream_mode 参数🔴 必须深钻核心概念，四种模式是面试高频
updates 模式🔴 必须深钻最常用的 agent 流式模式
messages 模式🔴 必须深钻Token 级流式，打字机效果核心
custom 模式🔴 必须深钻自定义流式，工具内进度输出
多模式组合🟡 建议掌握实战常见，需理解 (mode, chunk) 元组
stream / astream🟡 建议掌握同步 vs 异步的选择
StreamWriter 机制🟡 建议掌握底层实现原理
Agent 执行流程🟡 建议掌握理解 superstep 才能理解流式粒度
content_blocks 结构🟡 建议掌握消息内容的数据结构
values 模式🟢 了解即可较少使用，全量快照输出
debug 模式🟢 了解即可开发调试用，非生产核心

交叉关联

  • stream_mode 的粒度与 Agent 的 superstep 概念紧密相关（每个 superstep 触发一次 updates 事件）
  • custom 模式依赖 get_stream_writer()，其底层实现与 LangGraph 的 context 机制相关
  • messages 模式中的 metadata["langgraph_node"] 与 Agent 的 节点名称（model / tools）对应
  • summarization_middleware 和 remove_message 等中间件会在流式过程中影响状态，需理解其执行时机
  • 多模式组合需要理解 (mode, chunk) 元组 的迭代模式，类似 Python 枚举

学习路径

建议顺序：Agent 执行流程 → updates → messages → custom → 多模式组合 → StreamWriter 机制 → content_blocks → values / debug
